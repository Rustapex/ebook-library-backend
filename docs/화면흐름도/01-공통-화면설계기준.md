# ABC 공통 화면설계 기준

- 프로젝트: Acorn Book Cloud(ABC) 전자책 대여 서비스
- 기준 화면: PC Web 1920px
- User 콘텐츠 폭: 1440px
- Admin 콘텐츠 폭: 1540px
- 기준 문서: `api-spec(final).md`, `ebook-rental-table-layout-final.xlsx`
- 정책 우선순위: 문서 간 충돌 시 API/동작은 `api-spec(final).md`, 데이터 테이블/컬럼명은 `ebook-rental-table-layout-final.xlsx`를 최우선 기준으로 사용한다.

## 1. 문서 적용 원칙

| 항목 | 적용 기준 |
|---|---|
| 비회원 | 도서 탐색과 공지 조회 가능. 회원가입, 로그인, 아이디 찾기 접근 가능. 비회원 비밀번호 재설정은 API final 범위에서 제외한다. 대여, 즐겨찾기, 리뷰 작성, 신고, 마이페이지 기능은 로그인 후 사용 |
| 회원 | `MEMBER.status = JOINED`인 회원만 User 화면 전체 사용. `SANCTIONED`, `WITHDRAWN`, `DEACTIVATED` 계정은 로그인 또는 주요 활동 요청 제한 |
| 관리자 | 로그인 성공 후 `MEMBER.role = ADMIN`이면 `A-001 관리자 대시보드`로 이동 |
| 회원 탈퇴 | 물리 삭제하지 않고 `WITHDRAWN` 상태로 변경 |
| 결제 | 결제수단은 `CARD`만 제공. 쿠폰과 포인트는 할인/차감 수단이며, 완료된 `PAID` 결제만 저장 |
| 포인트 | 현재 잔액은 `MEMBER.point_balance`, 이력은 `POINT_HISTORY` 기준으로 표시. 유형은 `CHALLENGE_REWARD`, `REVIEW_REWARD`, `PAYBACK`, `EVENT_REWARD`, `PAYMENT_USE`, `ADMIN_ADJUST`만 사용. 포인트는 만료되지 않으므로 소멸예정 포인트 UI는 제공하지 않음 |
| 리뷰 | 첫 읽기 시작 이후 도서 상세에서 작성/수정/삭제. 회원+도서 기준 리뷰 1개이며, 사용자 삭제는 `DELETED`, 관리자 숨김은 `HIDDEN`으로 처리. 마이페이지에서 내 리뷰 목록과 상세 진입 제공 |
| 출판사 정보 | 도서 목록/검색/상세/관리 화면에서 출판사명만 표시 |
| 알림 | 대여, 결제, 쿠폰, 공지, 이벤트, 신고 처리 결과, 희망도서, 챌린지 알림을 `U-019 알림 내역`에서 조회. 알림 본문은 저장하지 않고 UI는 유형, 제목, 연결 대상, 읽음 여부, 일시만 표시 |
| 신고 | 별도 전체 화면 없이 도서 상세의 모달에서 책/리뷰 신고만 접수 |
| 제외 기능 | 채팅과 독립 신고 화면은 프로젝트 DB 및 화면 범위에서 제외 |
| 도서 상태 | User/Admin 도서 화면에서 `BOOK.status`는 `AVAILABLE`, `HIDDEN`, `INACTIVE`만 사용. `ACTIVE`는 출판사, 저자, 카테고리, 쿠폰 등 기준정보 상태에만 사용 |
| 신고 상태 | 화면 라벨은 접수/대기, 처리 중, 완료, 반려로 표시하고 코드값은 `WAITING`, `PROCESSING`, `DONE`, `REJECTED`로 매핑 |

### 2.3 카테고리 메뉴

카테고리는 `CATEGORY` 테이블의 활성 데이터로 구성한다. 초기 화면설계용 권장 대분류는 다음과 같다.

| 표시 순서 | 대분류 | 하위 분류 예시 |
|---:|---|---|
| 1 | 소설 | 한국소설, 영미소설, 일본소설, 장르소설 |
| 2 | 에세이 | 일상, 여행, 감성, 명상 |
| 3 | 인문 | 철학, 심리, 사회, 문화 |
| 4 | 경제·경영 | 경제, 경영, 재테크, 마케팅 |
| 5 | 자기계발 | 성공, 시간관리, 커리어, 인간관계 |
| 6 | IT·프로그래밍 | Java, JavaScript, 데이터베이스, 클라우드 |
| 7 | 과학 | 자연과학, 공학, 수학, 환경 |
| 8 | 역사 | 한국사, 세계사, 인물 |

카테고리 클릭 시 `categoryId`를 전달하여 `U-006 도서 목록`으로 이동한다. 실제 명칭과 순서는 관리자 `A-007 카테고리 관리`에서 변경한다.

## 5. 공통 UI 상태

| 상태 | 표시 내용 | 제공 버튼 |
|---|---|---|
| 로딩 | 스켈레톤 또는 `데이터를 불러오는 중입니다.` | 없음 |
| 빈 목록 | 화면별 빈 상태 문구 | `홈으로`, `도서 찾기` 등 |
| 로그인 필요 | `로그인 후 이용할 수 있습니다.` | `로그인`, `취소` |
| 권한 없음 | `접근 권한이 없습니다.` | `이전 화면` |
| 제재 회원 | `현재 계정은 이용이 제한되었습니다.` | `확인` |
| 처리 성공 | 성공 토스트와 변경된 결과 | 필요 시 연결 화면 |
| 입력 오류 | 해당 필드 하단 오류 문구 | 현재 화면 유지 |
| 서버 오류 | `처리 중 오류가 발생했습니다.` | `다시 시도` |

## 7. 최신 정책 적용 기준

| 정책 영역 | 이번 화면설계 적용 |
|---|---|
| 인증 | 로그인 성공 대상은 `JOINED`이며 `SANCTIONED`, `WITHDRAWN`, `DEACTIVATED`는 로그인 또는 주요 활동을 제한한다. 비회원 비밀번호 재설정은 `api-spec(final).md` 기준 제외하고, 로그인 회원의 비밀번호 변경만 `U-015`에서 `API-ME-003`으로 처리한다. |
| 도서 상세 | 도서 정보, 대여, 리뷰/별점, 즐겨찾기, 책/리뷰 신고, 추천 도서, 보유 도서관 연결만 제공 |
| 결제 | 결제수단은 `CARD`만 표시하고 쿠폰과 포인트는 할인/차감 수단으로 계산. 완료된 `PAID` 결제만 저장/표시 |
| 포인트/쿠폰 | 포인트 현재 잔액은 `MEMBER.point_balance`, 포인트 이력은 `POINT_HISTORY`, 쿠폰 만료일과 만료 예정 여부는 `MEMBER_COUPON.expires_at` 기준으로 목록에 표시. 포인트는 만료되지 않으므로 소멸예정 포인트 UI는 제공하지 않음 |
| 대여 | 대여 상태는 `READY`, `READING`, `OWNED`만 표시하고 대여 종료 후 재이용 안내로 처리 |
| 리뷰/별점 | 리뷰와 별점은 분리한다. 둘 다 회원+도서 기준 1개이며, 별점은 생성 후 수정/삭제할 수 없음 |
| 신고/제재 | 책/리뷰 신고만 접수한다. 리뷰 신고 처리 결과는 필요 시 `SANCTION_HISTORY`와 회원 현재 제재 정보로 이어짐 |
| 알림/공지 | 알림은 유형, 제목, 연결 대상, 읽음 여부, 일시만 표시. 공지 알림 생성 여부는 `NOTICE.notify_yn` 기준 |
| 희망도서 | `BOOK_REQUEST_CANDIDATE` 후보 단위 집계와 회원별 신청 row를 함께 표시. 검토 중은 후보 상태 `IN_REVIEW`로만 표시하고 `BOOK_REQUEST.request_status`에는 저장하지 않음 |
| 컬렉션 | 시리즈/이벤트 도서 묶음은 `COLLECTION`, `COLLECTION_BOOK` 기준으로 관리하고 이벤트는 `COLLECTION.collection_type = EVENT`로 구분 |
