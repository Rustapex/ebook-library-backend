## 4. A-003 회원 상세/상태 관리

| 영역 | 표시 내용 |
|---|---|
| 기본 정보 | 아이디, 이름, 이메일, 전화번호, 생년월일, 성별 |
| 계정 정보 | 역할, 상태, 등급, 포인트, 제재 이력 요약, 현재 유효 제재 |
| 이용 요약 | 대여, 결제, 리뷰, 책/리뷰 신고, 독서 통계 |
| 탭 | 대여 내역, 결제 내역, 리뷰 내역, 책/리뷰 신고 내역, 포인트 이력, 제재 이력 |

| 버튼 | 기능 | 이동/결과 |
|---|---|---|
| `상태 변경` | `JOINED/SANCTIONED/WITHDRAWN/DEACTIVATED`와 사유 저장. `SANCTIONED`는 제재 유형, 시작일, 종료일 입력 | 현재 화면 |
| `포인트 지급/차감` | 금액과 사유 입력 | 현재 화면 갱신 |
| `리뷰 전체보기` | 해당 회원 리뷰 필터 적용 | 리뷰 내역 탭 |
| `대여 전체보기` | 해당 회원 필터 적용 | `A-008` |
| `결제 전체보기` | 해당 회원 필터 적용 | `A-009` |
| `목록으로` | 회원 목록 복귀 | `A-002` |

리뷰 내역은 `REVIEW`와 `RATING` 기준으로 도서, 리뷰 상태, 별점, 작성일, 수정일을 표시한다. 포인트 현재 잔액은 `MEMBER.point_balance`, 포인트 이력은 `POINT_HISTORY` 기준으로 표시한다. 포인트는 만료되지 않으므로 소멸예정 포인트 탭은 제공하지 않는다. 관리자는 회원 비밀번호를 직접 확인하거나 변경하지 않는다. 회원 상태 변경에서 제재가 필요한 경우 `sanctionType`, `startedAt`, `endedAt`, `reason`을 함께 저장한다.

연동 API: `API-ADMIN-MEMBER-002~004`

## 6. A-005 도서 등록

### 입력 구역

| 구역 | 입력 항목 |
|---|---|
| 기본 정보 | 제목, ISBN, 출판사명, 저자와 표시 순서 |
| 분류 | 카테고리, 장르 키워드, 해시태그 |
| 대여 | 무료/유료, 대여 가격, 기본 대여일 |
| 표시 | 표지 이미지 URL, 상태(`AVAILABLE/HIDDEN/INACTIVE`) |
| 상세 | 책 소개, 목차, 출판사 리뷰, 상세 내용 |
| 전자책 본문 | 전체 페이지, 페이지 번호, 페이지 텍스트 본문 |

| 버튼 | 기능 | 이동/결과 |
|---|---|---|
| `저자 추가` | 저자 입력 행 추가 | 현재 화면 |
| `페이지 추가` | 페이지 본문 행 추가 | 현재 화면 |
| `등록` | 전체 검증 후 도서 생성 | 성공 시 `A-004` |
| `취소` | 입력 폐기 | `A-004` |

ISBN 중복, 유료 도서 가격 0원, 페이지 번호 중복을 오류로 표시한다. 상세 입력은 책 소개, 목차, 출판사 리뷰, 상세 내용으로 제한한다. 전자책 본문은 `BOOK_PAGE.page_content` 텍스트로만 등록하며 파일 URL, 파일 유형, 파일 크기는 입력하지 않는다.

연동 API: `API-ADMIN-BOOK-002`, `API-ADMIN-REQUEST-002`

## 11. A-010 신고 관리

| 필터 | 값 |
|---|---|
| 대상 | 책, 리뷰 |
| 상태 | 접수/대기, 처리 중, 완료, 반려 |

신고 상태 라벨은 접수/대기, 처리 중, 완료, 반려로 표시하고 코드값은 `WAITING`, `PROCESSING`, `DONE`, `REJECTED`로 매핑한다.

| 테이블 컬럼 | 내용 |
|---|---|
| 신고번호 | 대상별 신고 ID |
| 대상 유형/대상 | 책, 리뷰 |
| 신고자 | 회원 정보 |
| 신고 유형 | 신고 사유 코드 |
| 상태 | 처리 상태 |
| 접수일 | 신고 생성일 |
| 관리 | 상세, 처리 |

| 버튼 | 기능 | 결과 |
|---|---|---|
| `상세보기` | 신고 내용과 원본 확인 | 상세 패널 |
| `처리 중` | 상태 변경 | 목록 갱신 |
| `완료` | 처리 결과 입력 | 신고자 알림 생성 |
| `반려` | 반려 사유 입력 | 신고자 알림 생성 |
| `리뷰 숨김` | 리뷰 신고 처리 중 관리자 판단 | `REVIEW.status = HIDDEN` 처리 |

신고 관리는 책/리뷰만 제공한다. 사용자 본인 삭제는 `DELETED`, 관리자 리뷰 숨김은 `HIDDEN`으로 구분한다. 리뷰 신고 처리에서 회원 제재가 필요하면 `SANCTION_HISTORY`에 `sanction_type`, `started_at`, `ended_at`, `reason`을 저장하고 필요 시 `MEMBER.status = SANCTIONED`로 갱신한다.

연동 API: `API-ADMIN-REPORT-001`(`GET /api/v1/admin/reports`), `API-ADMIN-REPORT-002`(`PATCH /api/v1/admin/reports/{targetType}/{reportId}/status`)
관련 테이블: `BOOK_REPORT`, `REVIEW_REPORT`, `MEMBER`, `BOOK`, `REVIEW`, `SANCTION_HISTORY`, `NOTIFICATION`, `ADMIN_AUDIT_LOG`

## 12. A-011 희망도서 관리

| 영역 | 표시 내용 |
|---|---|
| 필터 | 신청, 검토 중, 승인, 반려 |
| 목록 | 후보 제목, 후보 저자, 후보 출판사, 신청자 수, 최초 신청일, 후보 상태 |
| 상세 | 신청자 목록, 개별 신청 제목/저자/출판사, 신청 사유, 신청 상태 |

| 버튼 | 기능 | 이동/결과 |
|---|---|---|
| `검토 시작` | 후보 상태를 검토 중으로 변경 | 현재 화면 |
| `신청자 보기` | 해당 후보의 신청 회원 목록 조회 | 상세 패널 |
| `승인 및 도서 등록` | 후보 정보를 등록 폼에 전달 | `A-005` |
| `승인 완료` | 후보와 연결된 신청 row 일괄 승인 | 현재 화면, 사용자 알림 생성 |
| `반려` | 후보와 연결된 신청 row 일괄 반려 | 현재 화면, 사용자 알림 생성 |

희망도서는 제목+저자+출판사를 정규화해 후보 단위로 집계한다. ISBN은 신청 단계에 저장하지 않고 도서 등록 시 입력한다. `검토 중`은 `BOOK_REQUEST_CANDIDATE.candidate_status = IN_REVIEW`로만 저장하며 회원별 `BOOK_REQUEST.request_status`는 `REQUESTED/APPROVED/REJECTED`만 사용한다.

연동 API: `API-ADMIN-REQUEST-001`(`GET /api/v1/admin/book-request-candidates`), `API-ADMIN-REQUEST-002`(`PATCH /api/v1/admin/book-request-candidates/{candidateId}/status`)
관련 테이블: `BOOK_REQUEST_CANDIDATE`, `BOOK_REQUEST`, `MEMBER`, `BOOK`, `NOTIFICATION`, `ADMIN_AUDIT_LOG`
