# 외부 도서 API(PR #23) 실키 검증 계획

작성일: 2026-07-03
대상 PR: https://github.com/shangpa/AcornProject/pull/23 (`feat(book): 외부 도서 API 통합 및 알라딘 카테고리 자동 매핑`, main에 병합 완료, `feature/catalog-user-api`에도 merge 반영됨 — `a8f2d38`)
배경: API 담당자가 `.env`에 정보나루/네이버/알라딘 실키를 채워줬다고 함. 실제로 외부 API를 정상적으로 받아오는지 확인이 필요함.

주의: `.env` 파일 원문은 읽지 않았음. 아래 내용은 `.env.example`, `application.properties`, 소스 코드, PR #23 본문만 근거로 작성했음.

---

## 1. PR #23 요약 (gh cli로 확인)

- 정보나루/네이버/알라딘 3곳의 ISBN13 단건 조회를 병합해 `book_isbn_temp`에 저장하고, 관리자 승인 시 실제 `book`으로 이관하는 1차 파이프라인.
- 관리자 API 4개: `lookup`(preview) → `fetch`(temp upsert) → `list`(후보 목록) → `approve`(실제 book 이관).
- 승인 시 `categoryIds`를 비워두면 알라딘 카테고리 경로를 내부 `category` 트리에 자동 생성/재사용.
- PR 본문에 "DB 변경은 수동 반영 필요"라고 명시돼 있음 — `schema.sql`이 `CREATE TABLE IF NOT EXISTS`라 기존에 이미 있던 로컬 DB에는 새 컬럼이 자동으로 안 생김.

## 2. 코드 수정이 필요한지 여부 판단

**결론: 코드 수정은 원칙적으로 불필요.** PR #23이 이미 `feature/catalog-user-api`에 병합됐고(`a8f2d38`), `./gradlew.bat build`도 통과했음. 지금 필요한 건 코드가 아니라 **DB 스키마 반영**과 **환경변수 확인**이다. 실제로 API를 호출해봤을 때 매핑이 깨지는 케이스가 나오면, 그때 아래 "4. 문제 발생 시 볼 파일"을 참고해서 수정하면 된다.

## 3. 지금 반영/확인해야 할 것 (파일별 이유)

| 대상 | 무엇을 확인/수정하나 | 왜 |
|---|---|---|
| 로컬 MySQL DB (코드 아님, DB 자체) | PR #23 본문의 ALTER 3개를 직접 실행했는지 확인 | `spring.jpa.hibernate.ddl-auto=validate`(`application.properties:19`)라서, `category`/`book_isbn_temp` 테이블에 새 컬럼이 없으면 **앱이 아예 기동을 못 함**. `spring.sql.init.mode=always`+`continue-on-error=true`(`application.properties:13,16`)라 `schema.sql`의 `CREATE TABLE IF NOT EXISTS`는 기존 테이블에 컬럼을 추가해주지 않고, ALTER 실패도 조용히 무시됨 |
| `.env` (원문 미확인, 사용자가 직접 확인) | `BOOK_API_ENABLED=true`인지, `INFONARU_KEY`/`NAVER_CLIENT_ID_1`/`NAVER_CLIENT_SECRET_1`/`ALADIN_TTB_KEY_1`이 실제로 채워졌는지 | `AladinBookClient.java:35`, `NaverBookClient.java:34`, `InfoNaruBookClient.java:35`가 각각 `properties.isEnabled()`가 `false`면 **아예 외부 호출을 안 하고 스킵**함. 키가 있어도 `BOOK_API_ENABLED=false`(`.env.example` 기본값)면 결과가 항상 비어있는 것처럼 보여서 "안 되는 줄" 착각하기 쉬움 |
| 회원 계정의 `role` | 테스트용 계정 하나를 `role='ADMIN'`으로 바꿔야 함 | `/api/v1/admin/**`은 `SecurityConfig.java:59`에서 `hasRole("ADMIN")`으로 막혀 있고, `data.sql`에 ADMIN 계정 시드가 없음. 일반 회원 JWT로는 lookup/fetch/list/approve 전부 403 |

## 4. 문제 발생 시 볼 파일 (실제로 API가 이상하게 오면)

| 증상 | 의심 지점 |
|---|---|
| `providers`가 전부 `FAILED`/`FAILED_RETRYABLE` | 키 오타, `BOOK_API_ENABLED=false`, 방화벽/타임아웃(`BOOK_API_TIMEOUT_MS`) → `BookApiProperties.java`, 각 `*BookClient.java`의 요청 URL/파라미터 |
| 일부 필드만 비어있음(`title`은 있는데 `coverImageUrl` 없음 등) | 응답 파싱 매핑 문제 → 해당 provider의 `*BookClient.java`가 외부 API JSON을 `ProviderBookData`로 변환하는 부분 |
| `approve` 호출 시 500/DB 에러 | `category` 테이블 UNIQUE 제약(`uk_category_aladin_category_id`, `uk_category_parent_name`)이 없거나, `book_isbn_temp.aladin_category_name` 컬럼이 없어서 → 2번 표의 "로컬 MySQL DB" 항목부터 재확인 |
| 알라딘 카테고리 자동 생성이 이상하게 동작 | `category/service/AladinCategoryImportService.java`, `AladinCategoryUpsertService.java` (동시성 방어를 `REQUIRES_NEW`로 격리한 부분) |

## 5. 화면 없이 직접 확인하는 방법 (Swagger / API 직접 호출)

이 프로젝트는 백엔드 API 서버라 별도 화면은 없음. `SecurityConfig.java:57`에서 Swagger UI는 인증 없이 열려 있음.

### 5-1. 사전 준비

1. 로컬 MySQL에서 PR #23 본문의 ALTER 3개를 직접 실행했는지 확인 (안 했으면 실행):
   ```sql
   ALTER TABLE book_isbn_temp ADD COLUMN aladin_category_name VARCHAR(255) NULL;
   ALTER TABLE category
     ADD COLUMN aladin_category_id VARCHAR(20) NULL,
     ADD COLUMN aladin_category_name VARCHAR(255) NULL;
   ALTER TABLE category
     ADD CONSTRAINT uk_category_aladin_category_id UNIQUE (aladin_category_id),
     ADD CONSTRAINT uk_category_parent_name UNIQUE (parent_category_id, category_name);
   ```
   (이미 반영돼 있으면 에러 나는 게 정상이니 무시)
2. `.env`에서 `BOOK_API_ENABLED=true`인지, 키 4개가 채워졌는지 본인이 직접 확인 (Claude는 이 파일을 읽지 않음).
3. 테스트용 회원의 `role`을 `ADMIN`으로 변경:
   ```sql
   UPDATE member SET role = 'ADMIN' WHERE login_id = '테스트계정아이디';
   ```

### 5-2. 앱 기동 및 Swagger 접속

```powershell
.\gradlew.bat bootRun
```

- 브라우저에서 `http://localhost:8080/swagger-ui/index.html` 접속
- 콘솔에 Hibernate `validate` 에러 없이 정상 기동되는지부터 확인 (여기서 실패하면 4-1 DB ALTER 미반영이 원인)

### 5-3. 로그인해서 ADMIN JWT 받기

- Swagger에서 `Auth` 태그의 `POST /api/v1/auth/login` 실행 → 위에서 `role='ADMIN'`으로 바꾼 계정으로 로그인
- 응답의 `accessToken`을 Swagger 우측 상단 `Authorize` 버튼에 `Bearer {토큰}` 형식으로 입력

### 5-4. 순서대로 호출하며 확인

1. **`GET /api/v1/admin/books/external/lookup?isbn13=실제ISBN13`** (`Admin External Book` 태그)
   - 확인 포인트: 응답 `providers.infonaruStatus/naverStatus/aladinStatus`가 `SUCCESS_HAS_DATA`인지 (`FAILED`면 4번 표 참고). `title`/`author`/`coverImageUrl`이 채워졌는지. `warnings` 배열이 비어있는지.
2. **`POST /api/v1/admin/book-isbn-temps/fetch`** (`Admin Book ISBN Temp` 태그), body `{"isbn13": "..."}`
   - 확인 포인트: `statusCd`가 `READY`(제목 확보 성공)인지 `PENDING`(제목 못 가져옴)인지.
3. **`GET /api/v1/admin/book-isbn-temps?status=READY`**
   - 방금 fetch한 항목이 목록에 보이는지 확인.
4. **`POST /api/v1/admin/book-isbn-temps/{tempId}/approve`**, body는 `title`/`publisherName`/`authors`/`rentalType`(FREE|PAID)/`rentalPrice`/`status`(AVAILABLE|HIDDEN|INACTIVE) 필수, `categoryIds`는 비워두면 알라딘 카테고리 자동 매핑 테스트 가능, `pages`는 뷰어 테스트하려면 최소 1개 이상 넣기
   - 확인 포인트: 201 응답, DB에 `book`/`book_category`/필요시 `category` 신규 행이 생겼는지.

### 5-5. curl로 확인하고 싶을 때 (Swagger 대신)

```bash
TOKEN="로그인으로 받은 accessToken"
curl -s "http://localhost:8080/api/v1/admin/books/external/lookup?isbn13=9788936434267" \
  -H "Authorization: Bearer $TOKEN" | jq .
```

## 6. 남은 확인 사항

- PR #23 작성자가 "approve API 실기동 검증은 DB ALTER 반영 후 리뷰어가 재확인 필요"라고 명시함 — 위 5번 절차의 approve 단계가 이번 검증의 핵심.
- 실키 호출 결과 provider별 응답이 정상인지는 외부 API 쿼터/네트워크 상태에 따라 달라질 수 있으므로, 한 번 실패했다고 바로 코드 문제로 단정하지 말고 재시도 후 판단할 것.
