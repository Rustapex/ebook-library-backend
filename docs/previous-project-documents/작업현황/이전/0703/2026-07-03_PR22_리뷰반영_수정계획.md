## 2. 항목별 상세 계획

### 2-1. 대여 만료 검증 (`RentalService.java:17`)

**현재 코드**
```java
public BookRental getOwnedRentalOrThrow(Long rentalId, Long memberId) {
    BookRental rental = bookRentalRepository.findById(rentalId)
            .orElseThrow(() -> new BusinessException(ErrorCode.RENTAL_NOT_FOUND));
    if (!rental.getMember().getMemberId().equals(memberId)) {
        throw new BusinessException(ErrorCode.AUTH_ACCESS_DENIED);
    }
    return rental;
}
```
소유권만 확인하고 `rentalEndAt`, `rentalStatus`는 전혀 보지 않음.

**근거 (결정 완료 — 0번 섹션 참고)**

`docs/API 명세/api-spec(final).md:92,109,387`:
> 대여 상태는 `READY`, `READING`, `OWNED`만 사용. **반납/연체 상태 없음**. 연체료 결제 제외(범위 밖).

즉 스펙상 "EXPIRED"라는 상태값 자체는 만들면 안 됨. 대신 `book_rental.rental_end_at`(NOT NULL) 컬럼은 이미 있으므로, **새 상태값을 추가하지 않고 시간 비교로만 접근을 막는 방식**으로 확정.

`docs/화면흐름도/02-User-상세화면설계도.md:290-291`, `04-전체-화면이동흐름.md:79`: `OWNED`=소장(영구 소유)으로 명시돼 있어 만료 검사 제외 확정.

- `rentalStatus`가 `OWNED`이면 만료 검사 skip (영구 소장)
- `READY`/`READING`이면 `rentalEndAt.isBefore(now())`일 때 접근 차단, `RENTAL_EXPIRED`(403) 발생

**수정안**
```java
public BookRental getOwnedRentalOrThrow(Long rentalId, Long memberId) {
    BookRental rental = bookRentalRepository.findById(rentalId)
            .orElseThrow(() -> new BusinessException(ErrorCode.RENTAL_NOT_FOUND));
    if (!rental.getMember().getMemberId().equals(memberId)) {
        throw new BusinessException(ErrorCode.AUTH_ACCESS_DENIED);
    }
    if (!"OWNED".equals(rental.getRentalStatus()) && rental.getRentalEndAt().isBefore(LocalDateTime.now())) {
        throw new BusinessException(ErrorCode.RENTAL_EXPIRED);
    }
    return rental;
}
```

**신규 ErrorCode 추가 필요** (`ErrorCode.java`, Rental 섹션):
```java
RENTAL_EXPIRED(HttpStatus.FORBIDDEN, "RENTAL_EXPIRED", "대여 기간이 만료되었습니다."),
```

이 메서드는 `ViewerService`(뷰어 조회/진행저장), `BookmarkService`(북마크 3개 메서드) 전부가 거치므로, 여기 한 곳만 고치면 4개 API 전부에 적용됨.

### 2-2. `saveProgress()` 실제 페이지 존재 검증 (`ViewerService.java:54-60`)

**현재**: `request.currentPage() > book.getTotalPages()` 범위만 검사. `book_page`에 실제 그 페이지가 있는지는 확인 안 함 (`totalPages`와 실제 저장된 페이지 수가 어긋날 수 있음).

**수정안**: `getPage()`에서 이미 쓰는 것과 동일하게 `bookPageRepository.findByBook_BookIdAndPageNo(...)`로 실존 확인.

```java
public ProgressResponse saveProgress(Long rentalId, ProgressUpdateRequest request, Long memberId) {
    BookRental rental = rentalService.getOwnedRentalOrThrow(rentalId, memberId);
    Book book = rental.getBook();

    bookPageRepository.findByBook_BookIdAndPageNo(book.getBookId(), request.currentPage())
            .orElseThrow(() -> new BusinessException(ErrorCode.BOOK_PAGE_NOT_FOUND));

    ReadingProgress progress = ...
```
`totalPages` 초과 체크(`request.currentPage() > book.getTotalPages()`)는 페이지 실존 체크로 대체되므로 제거 가능 (실존하지 않으면 어차피 걸림).

### 2-3. 북마크 저장 `saveAndFlush()` 적용 (`BookmarkService.java:36`)

**현재**
```java
Bookmark bookmark = bookmarkRepository.save(Bookmark.create(rental, request.pageNo()));
```
`IDENTITY` 전략이라 보통 `save()` 시점에 즉시 INSERT가 나가긴 하지만, 리뷰어는 flush 타이밍에 따라 트랜잭션 커밋 시점까지 `DataIntegrityViolationException`이 미뤄질 가능성을 지적함. `saveAndFlush()`로 바꾸면 그 자리에서 확실히 예외가 던져짐.

**수정안**
```java
Bookmark bookmark = bookmarkRepository.saveAndFlush(Bookmark.create(rental, request.pageNo()));
```

## 3. Postman + Swagger 동시 테스트 계획

> 참고: 이 항목은 GitHub(PR 코멘트/커밋)에 근거가 없는 별도 구두 요청 사항입니다.

2-1~2-4 수정이 실제로 동작하는지, 자동화 테스트뿐 아니라 Postman/Swagger로 직접 호출해서 같이 확인합니다.

| 시나리오 | 방법 | 확인할 것 |
|---|---|---|
| 정상 뷰어 조회 | Swagger `GET /api/v1/rentals/{rentalId}/pages/{pageNo}` | 200, `progressRate` 갱신 |
| 만료된 대여로 뷰어 접근 (2-1 검증) | Postman으로 `rental_end_at`을 과거로 만든 rental에 대해 호출 | 403 `RENTAL_EXPIRED` |
| 존재하지 않는 페이지로 progress 저장 (2-2 검증) | Postman `PUT /api/v1/rentals/{rentalId}/progress` body `currentPage`를 실제 없는 값으로 | 404 `BOOK_PAGE_NOT_FOUND` |
| 북마크 동시 중복 요청 (2-3 검증) | Postman Runner로 같은 페이지 북마크 요청 2회 동시 실행 | 두 번째 요청 409 `BOOKMARK_ALREADY_EXISTS` (500 아님) |
| 존재하지 않는 페이지 조회 (2-4 검증) | Swagger `GET /pages/{pageNo}`에 없는 페이지 번호 | 404 `BOOK_PAGE_NOT_FOUND` (기존엔 400 `VALIDATION_ERROR`였음) |

Swagger는 `http://localhost:8080/swagger-ui/index.html`에서 위 정상 케이스/에러코드 확인용으로, Postman은 만료 대여·동시 요청처럼 Swagger로 조작하기 번거로운 시나리오(DB 값 직접 세팅, Collection Runner 동시 요청)에 사용합니다.
