## 2. API-ADMIN-STAT-001 — 관리자 통계 조회 실시간 집계 확인 (§1-3)

> **시작 전 확인**: "0."의 1~4번, "1."의 SQL이 전부 실행됐는지 확인 후 진행.

Swagger 요청:

```text
GET /api/v1/admin/statistics?periodType=TOTAL
인증: 관리자(adminuser)
```

기대:

- `200 OK`, `data`의 각 필드가 §1의 `expected*` 값과 **정확히 일치**.
- `data.reviewCount = 0`, `data.reportCount = 0`(review 패키지 Repository 부재로 항상 0, §4-4 참고).
- `data.updatedAt`이 방금 호출한 시각과 가까움(배치가 아니라 요청 시점에 계산되므로).
- (§1-1 확인, 선택 사항) Swagger UI에서 `baseDate` 파라미터에 마우스를 올리면 "현재 미사용 파라미터입니다..." 설명이 보이는지 육안 확인.
- 실제로 다르게 나오면 어디를 봐야 하는지:
  - **값이 하나라도 다르면** → `AdminStatisticService`의 count/sum 쿼리(`countByStatus`, `countByBook_RentalType`, `countByCompletedYn`, `sumAmountByPaymentStatus`) 중 하나가 실제 컬럼/CHECK 값과 안 맞는 것.
  - **404가 나오면** → `periodType=TOTAL`이 정확히 들어갔는지, 서버가 최신 코드로 재기동됐는지(위 "0." 1번) 확인.

사후 DB 확인:

```sql
SELECT admin_stat_id, period_type, age_band, updated_at
FROM admin_statistic
WHERE period_type = 'TOTAL' AND age_band = 'ALL';
```

확인 기준: "1."에서 본 `updated_at`과 **정확히 같아야 정상**(더 이상 아무도 이 테이블에 쓰지 않으므로 값이 바뀌면 안 됨).

## 6. API-ADMIN-AUDIT-001 — 감사 로그 size 상한 클램프 확인 (§1-4)

Swagger 요청 1:

```text
GET /api/v1/admin/audit-logs?size=500
인증: 관리자(adminuser)
```

기대: `200 OK`, **`data.size = 100`**(500이 아니라 100으로 조용히 잘림 — `@Max` 400 에러 아님). `data.content`에 "5."에서 넣은 `SWAGGER_TEST_0711_SIZE_CLAMP` 행 포함.

Swagger 요청 2(클램프 미적용 구간 확인):

```text
GET /api/v1/admin/audit-logs?size=10
인증: 관리자(adminuser)
```

기대: `200 OK`, `data.size = 10` 그대로(100 이하 값은 클램프 없이 통과해야 정상).

사후 DB 확인:

```sql
SELECT COUNT(*) AS auditLogCount FROM admin_audit_log WHERE action_type = 'SWAGGER_TEST_0711_SIZE_CLAMP';
-- 1건 그대로 유지되어야 정상(조회로 데이터가 늘거나 줄지 않음)
```

## 7. 정리 — 테스트 전용 데이터 삭제 + 최종 무결성 확인

```sql
SET SQL_SAFE_UPDATES = 0;
DELETE FROM admin_audit_log WHERE action_type = 'SWAGGER_TEST_0711_SIZE_CLAMP';
SET SQL_SAFE_UPDATES = 1;

SELECT
  (SELECT COUNT(*) FROM admin_audit_log WHERE action_type = 'SWAGGER_TEST_0711_SIZE_CLAMP') AS remainingAuditLogCount,
  (SELECT updated_at FROM admin_statistic WHERE period_type = 'TOTAL' AND age_band = 'ALL') AS finalAdminStatisticUpdatedAt;
```

확인 기준:
- `remainingAuditLogCount = 0`
- `finalAdminStatisticUpdatedAt`이 "1."에서 기억해둔 값과 **정확히 같아야 정상**(다르면 어딘가 여전히 `admin_statistic`에 쓰고 있다는 뜻 — 회귀 버그).
