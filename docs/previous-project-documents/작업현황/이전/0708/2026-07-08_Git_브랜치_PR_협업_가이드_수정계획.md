## 3. Fetch 먼저 해야 하는지에 대한 반영 기준

정확한 Git 동작 기준:

- 터미널의 `git pull`은 내부적으로 `fetch` 후 `merge` 또는 설정에 따라 `rebase`를 수행한다.
- 따라서 터미널에서는 `git pull origin main`만으로도 최신 내용을 가져오고 병합할 수 있다.

문서 작성 기준:

- Sourcetree GUI 초보자 문서에서는 `Fetch(패치)`를 먼저 눌러 원격 상태를 화면에 갱신한 뒤 `Pull`을 누르는 방식으로 안내한다.
- 이유는 사용자가 `origin/main`이 어디까지 올라왔는지 그래프에서 먼저 확인할 수 있고, 원격에서 삭제된 브랜치 정리 옵션도 함께 안내할 수 있기 때문이다.
- 터미널 방식은 두 가지를 병행 안내한다.

```bash
# 초보자에게 흐름이 잘 보이는 방식
git fetch --prune origin
git switch main
git pull origin main

# 또는 pull 하나로 처리
git switch main
git pull origin main
```

## 5. 상세 수정 계획

### 5-1. 코드 블록 가독성 수정

현재 문제:

- `pre`는 어두운 배경인데 내부 `code`가 inline code 스타일을 그대로 받아 밝은 배경과 border를 표시한다.

수정 계획:

```css
pre code {
  background: transparent;
  border: 0;
  padding: 0;
  color: inherit;
  font-size: inherit;
}
```

추가 검토:

- `pre` 안의 명령어가 충분히 밝게 보이도록 `color`, `line-height`, `overflow-x` 유지
- inline `code`는 본문에서 계속 밝은 배경으로 표시

### 5-2. `6. main 최신화` Sourcetree GUI 절차 재작성

현재 문장:

- `main`으로 이동
- Pull 클릭
- 원격 브랜치가 `origin/main`인지 확인

수정 후 목표:

Sourcetree 초보자가 화면을 보고 그대로 따라 할 수 있게 단계별로 작성한다.

예상 문안:

1. 왼쪽 `브랜치` 목록에서 `main`을 더블클릭한다.
2. 상단 `패치(Fetch)` 버튼을 누른다.
3. 패치 옵션에서 다음을 확인한다.
   - `모든 원격 저장소에서 가져오기`: 체크
   - `리모트에서 제거된 브랜치 정리하기`: 체크
4. `확인`을 눌러 원격 저장소 정보를 먼저 갱신한다.
5. 상단 `Pull` 버튼을 누른다.
6. Pull 창에서 다음을 확인한다.
   - 원격 저장소: `origin`
   - 가져오기 위한 원격 브랜치: `main`
   - 가져온 뒤 병합 대상: 현재 로컬 `main`
   - 충돌이 없으면 묶어서 바로 커밋: 체크
7. `Pull` 버튼을 눌러 최신 `main`을 로컬에 반영한다.
8. History 그래프에서 `main`과 `origin/main` 위치가 맞는지 확인한다.

주의 문구:

- `main` 이동 전에 변경 파일이 있으면 먼저 commit하거나 stash 처리한다.
- `Pull`은 최신 내용을 가져와 현재 브랜치에 합치는 작업이므로, 현재 브랜치가 `main`인지 먼저 확인한다.

### 5-3. 터미널 `main 최신화` 절차 보강

수정 계획:

```bash
git status --short
git switch main
git fetch --prune origin
git pull origin main
```

설명 추가:

- `git fetch --prune origin`: 원격 저장소 상태와 삭제된 원격 브랜치 정보를 먼저 갱신
- `git pull origin main`: 원격 `main` 내용을 현재 로컬 `main`에 반영
- 변경 파일이 있으면 `git switch main` 또는 `git pull` 전에 commit/stash 여부를 판단

## 6. `PR 전 최신 main 병합` 수정 방향

Sourcetree GUI 예상 문안:

1. 작업 중인 내용을 commit하거나 stash해서 작업 폴더를 정리한다.
2. `main`으로 이동한다.
3. `패치(Fetch)`를 실행한다.
   - `모든 원격 저장소에서 가져오기`: 체크
   - `리모트에서 제거된 브랜치 정리하기`: 체크
4. `Pull`을 실행한다.
   - 원격 저장소: `origin`
   - 원격 브랜치: `main`
   - 충돌이 없으면 묶어서 바로 커밋: 체크
5. 작업 브랜치로 다시 이동한다.
6. `main`을 현재 작업 브랜치에 병합한다.
7. 충돌이 있으면 해결하고, 충돌이 없으면 테스트/빌드를 다시 실행한다.
8. 병합 결과가 생긴 작업 브랜치를 push한다.

터미널 예상 문안:

```bash
git status --short
git switch main
git fetch --prune origin
git pull origin main
git switch feature/member-login
git merge main
# 테스트/빌드 후
git push
```

## 7. `다른 팀원 PR merge 전달` 수정 방향

현재 문서의 취지는 유지하되 Sourcetree 초보자용 설명을 더 자세히 작성한다.

Sourcetree GUI 예상 문안:

1. 먼저 왼쪽 브랜치 목록에서 현재 브랜치가 내 작업 브랜치인지 확인한다.
2. 파일 상태 탭에서 아직 commit하지 않은 변경이 있는지 확인한다.
3. 미완료 변경이면 상단 또는 메뉴의 `스태시(Stash)` 기능으로 임시 보관한다.
4. `main`으로 이동한다.
5. `패치(Fetch)` 후 `Pull`을 실행한다.
6. 다시 내 작업 브랜치로 이동한다.
7. 최신 `main`을 내 작업 브랜치에 병합한다.
8. stash를 사용했다면 stash 목록에서 다시 적용한다.
9. 충돌 여부를 확인하고 테스트 후 push한다.

주의 문구:

- stash는 commit이 아니라 임시 보관이다.
- commit은 충돌을 없애는 기능이 아니라 내 작업을 이력으로 남기는 기능이다.
- 미완성 작업을 commit할지 stash할지는 팀 규칙에 따라 정하되, 초보자 문서에서는 stash를 우선 안내한다.

## 8. 설명 톤 수정 방향

현재 문제:

- 절차가 요약형이라 Git/Sourcetree 초보자가 화면에서 무엇을 눌러야 하는지 알기 어렵다.

수정 방향:

- 버튼명은 굵게 표시한다. 예: `패치`, `Pull`, `Branch`, `Push`, `스태시`
- 확인해야 하는 값은 code로 표시한다. 예: `origin`, `main`, `origin/main`
- 각 GUI 절차마다 “먼저 확인할 것 -> 누를 버튼 -> 옵션 확인 -> 실행 후 확인할 것” 순서로 작성한다.
- 터미널 명령은 GUI 절차 바로 옆에 같은 목적의 명령으로 배치한다.
- “왜 이 작업을 하는지”를 각 절차 앞에 한 문장으로 추가한다.

## 10. 예상 위험

- Sourcetree 버전에 따라 버튼명이나 옵션 문구가 다를 수 있다.
- 사용자의 Sourcetree가 한글 UI이므로 문서 기본은 한글 버튼명으로 쓰고, 필요한 경우 괄호로 영어명을 병기한다.
- `충돌이 없으면 묶어서 바로 커밋` 옵션은 Sourcetree 버전/설정에 따라 문구가 다를 수 있으므로, 문서에는 “보이면 체크” 또는 “팀 기준에 맞게 체크”처럼 과도하게 단정하지 않는 표현이 필요하다.
- `Fetch` 후 `Pull`을 안내하되, 터미널에서는 `pull`이 내부적으로 fetch를 포함한다는 설명을 넣어 혼동을 줄인다.
