- **1순위: `백엔드_공통_개발_규칙.md`**, **2순위: `api-spec(final).md`**.

### 2-5. `sort` enum 명세화 (코드 반영 완료, api-spec 문서화만 잔여)

- **현재 상태(확인됨)**: `BookService.java:211-245`(`sortFor`/`normalizeSort`)는 `title`/`popular`만 인식하고, 그 외(빈 값/오타 포함) 전부 `latest`로 조용히 fallback한다. 잘못된 값이 와도 에러가 나지 않는다.
- **파일**: `docs/API 명세/api-spec(final).md`, `src/main/java/com/acorn/abc/book/service/BookService.java`(`normalizeSort`)
- **구현 방식 검토 결과**: `sort`는 `@RequestParam`(바디 DTO `@Valid` 아님)이라 `@Pattern`+`@Validated`나 enum 타입 바인딩 방식은 둘 다 `GlobalExceptionHandler`에 `ConstraintViolationException`/`MethodArgumentTypeMismatchException` 핸들러를 새로 추가해야 400/`VALIDATION_ERROR`로 응답된다(현재 미지원 → 500으로 샘).
- **채택 방식(반영 완료)**: `normalizeSort`에서 `latest`/`title`/`popular` 외 값이면 `throw new BusinessException(ErrorCode.VALIDATION_ERROR)`로 코드 반영함(`BookService.java:236-245`, 2026-07-02). 같은 파일의 `normalizeRentalType`과 동일 패턴이라 `GlobalExceptionHandler`/`build.gradle` 무수정. 상세는 `2026-07-02_카탈로그API_변경이력.md` 참고.
- **잔여**: api-spec에 `latest/title/popular` 허용값 문서화는 아직 안 함(문서 최신화는 후순위 원칙에 따라 나중에 일괄 반영).
- **위험**: 지금은 잘못된 값이 조용히 `latest`로 처리되므로, 프론트가 오타난 `sort` 값을 보내고 있었다면 이 변경으로 정상 동작하던 요청이 400으로 바뀔 수 있다 — 프론트 쪽 실제 전송값 확인 후 적용 권장.
