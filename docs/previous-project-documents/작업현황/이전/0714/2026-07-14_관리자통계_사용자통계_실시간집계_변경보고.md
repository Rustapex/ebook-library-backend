## 7. 전달용 요약 문구

> 다시 확인한 결과, 기획과 달라지는 부분은 즐겨찾기 수와 관리자 현재 상태 KPI만이 아닙니다. 사용자 통계의 읽은 페이지 수는 "기간 중 새로 읽은 페이지"가 아니라 `last_read_at`이 기간 안에 있는 진행상황의 누적 도달 페이지 합산 근사치입니다. 관리자 통계에서는 전체 회원 수, 제재 회원 수, 이용 가능 도서 수가 기간별 값이 아니라 현재 기준이고, 신고 수는 미처리 신고가 아니라 상태 조건 없는 기간 내 신고 수입니다. 또 희망 도서 미처리 수와 도서별 완독 수/완독률은 현재 A-016 통계 응답에 없습니다. 프론트 문서는 이 항목들을 `이전: 기간별/미처리/도서별 통계`에서 `이후: 실시간 재계산 + 일부 현재 기준/일부 미제공`으로 분리해서 수정해야 합니다.

## 8. 남은 문서 반영 필요

- 기획 문서의 "별도 집계 table 저장"과 실제 구현의 실시간 집계 정책 차이를 반영해야 한다.
- 사용자 통계 "읽은 페이지 수"에는 B1 기준과 근사치 한계를 반드시 남긴다.
- A-016 문서에서 `신고`가 미처리 신고인지 기간 내 전체 신고인지 명확히 바꾼다.
- A-016 문서에서 희망도서 미처리 수, 도서별 완독 수/완독률이 현재 응답에 없다는 점을 표시하거나 백엔드 확장 필요 항목으로 분리한다.
- A-016 API 설명의 "TOTAL만 지원" 문구는 최신 백엔드 기준과 달라 교체해야 한다.
