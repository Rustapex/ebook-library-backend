# 챌린지 coupon 보상 실제 지급 로직 — Swagger 검증 체크리스트

작성일: 2026-07-09
관련 브랜치: `feat/challenge-coupon-reward-grant`
관련 계획 문서: `docs/작업현황/2026-07-09_쿠폰실제지급로직_구현계획.md`
관련 SQL: `api-test-results/쿠폰 지급/사전준비및원복.sql`
대상 코드(구현 완료, 서버 재시작 후 테스트할 것): `AdminChallengeRewardItemRequest`, `ChallengeService.validateRewardItems/updateChallenge/claimReward`, `ChallengeRewardClaimResponse`

이 문서와 SQL 파일은 같은 절 번호(`§0`~`§8`)를 서로 그대로 참조한다. **지금 SQL 파일에서 몇 번째 절까지 실행했는지 먼저 확인한 뒤**, 이 문서에서 같은 번호가 붙은 안내를 찾아 다음 순서로 진행한다. 반대로 이 문서를 보다가 "SQL §N 실행" 안내가 나오면 SQL 파일을 열어 그 절만 실행하고 돌아온다.

**방식**: 기존 데이터는 전혀 건드리지 않고 테스트 전용 `coupon`/`challenge`/`challenge_reward`/`challenge_progress`/`member_coupon` 행만 새로 추가한다(2026-07-08/0709 라운드에서 확립된 방식과 동일). 이번 검증은 어떤 테이블도 "비어 있는 상태"를 요구하지 않으므로(모든 판정이 새로 추가한 행 기준) 백업 테이블/뷰를 만들 필요는 없다.

## 3. API-ADMIN-CHALLENGE-002 — coupon 보상 등록 성공 (`PUT /api/v1/admin/challenges/{testChallengeId}`)

> **시작 전 확인**: "0."의 1~5번이 전부 체크됐는지 확인 후 진행.

Swagger 요청:

```text
PUT /api/v1/admin/challenges/{testChallengeId}
인증: 관리자(adminuser)
body:
{
  "challengeName": "SWAGGER_TEST_COUPONGRANT_쿠폰보상챌린지",
  "challengeType": "TOTAL",
  "targetAction": "ATTENDANCE",
  "targetCount": 1,
  "status": "ACTIVE",
  "rewards": [
    {
      "rewardType": "coupon",
      "rewardPoint": null,
      "couponId": {testCouponId},
      "rewardQuantity": 2
    }
  ]
}
```

기대:

- `200 OK`, `data.challengeId = {testChallengeId}`
- 실제로 다르게 나오면 어디를 봐야 하는지:
  - **`400 VALIDATION_ERROR`가 나오면** → `AdminChallengeRewardItemRequest`의 `@Pattern(regexp = "POINT|coupon")`이 실제로 반영됐는지, 서버가 최신 코드로 재시작됐는지 확인(위 "0." 1번). 또는 `validateRewardItems()`의 `coupon` 분기 조건(`couponId == null || rewardPoint != null`)이 잘못 걸렸는지 확인.
  - **`404 COUPON_NOT_FOUND`가 나오면** → `{testCouponId}`를 SQL §1에서 확인한 값과 다르게 넣었는지 확인.

사후 DB 확인(SQL §3 블록 실행):

```sql
SELECT challenge_reward_id, reward_type, reward_point, coupon_id, reward_quantity
FROM challenge_reward
WHERE challenge_id = @test_challenge_id;
```

확인 기준: `reward_type='coupon'`, `coupon_id={testCouponId}`, `reward_quantity=2`.

## 4. coupon 보상 등록 실패 — couponId 누락 (`PUT /api/v1/admin/challenges/{testChallengeId}`)

Swagger 요청: §3과 동일하되 `rewards[0].couponId`만 `null`로 변경.

```text
{
  "challengeName": "SWAGGER_TEST_COUPONGRANT_쿠폰보상챌린지",
  "challengeType": "TOTAL",
  "targetAction": "ATTENDANCE",
  "targetCount": 1,
  "status": "ACTIVE",
  "rewards": [
    { "rewardType": "coupon", "rewardPoint": null, "couponId": null, "rewardQuantity": 1 }
  ]
}
```

기대:

- `400 VALIDATION_ERROR`
- 실제로 다르게 나오면: **`200 OK`가 나오면** → `validateRewardItems()`의 `"coupon".equals(item.rewardType())` 분기에서 `item.couponId() == null` 체크가 빠졌는지 확인.

사후 DB 확인(SQL §4 블록 실행) — §3 값이 그대로 유지돼야 정상(실패 요청이 반영되면 안 됨):

```sql
SELECT challenge_reward_id, reward_type, reward_point, coupon_id, reward_quantity
FROM challenge_reward
WHERE challenge_id = @test_challenge_id;
```

확인 기준: 여전히 `coupon_id={testCouponId}`, `reward_quantity=2`(§3 값 그대로).

## 7. API-CHALLENGE-002 — coupon 보상 실수령 (`POST /api/v1/challenges/{testChallengeId}/reward`)

> **시작 전 확인**: §3의 coupon 보상 등록이 성공한 상태(`coupon_id={testCouponId}`, `reward_quantity=2`)이고, §6의 진행도 준비가 끝났는지 확인.

Swagger 요청:

```text
POST /api/v1/challenges/{testChallengeId}/reward
인증: 회원 testusera의 JWT
Body: 없음
```

기대:

- `200 OK`, `data.grantedCouponQuantity = 2`, `data.grantedPoint = 0`
- 실제로 다르게 나오면 어디를 봐야 하는지:
  - **`409 CHALLENGE_REWARD_TYPE_NOT_SUPPORTED`가 나오면** → `claimReward()`의 `"coupon".equals(reward.getRewardType()) && reward.getCoupon() != null` 분기가 빠졌거나, `reward.getCoupon()`이 `null`인지 확인(§3에서 coupon 등록이 실제로 됐는지 먼저 재확인).
  - **`grantedCouponQuantity`가 응답에 없으면** → `ChallengeRewardClaimResponse`에 필드 추가가 반영 안 됐거나 서버 미재시작.
  - **`404 MEMBER_NOT_FOUND`가 나오면(사실상 발생 안 해야 정상)** → `testusera`의 JWT가 아닌 다른 토큰으로 호출했는지 확인.

사후 DB 확인(SQL §7 블록 실행) — 이 테스트의 핵심:

```sql
SELECT reward_claimed_at
FROM challenge_progress
WHERE challenge_id = @test_challenge_id AND member_id = @member_id_a;
-- NOT NULL이어야 정상

SELECT member_coupon_id, member_id, coupon_id, coupon_status, issued_at, expires_at
FROM member_coupon
WHERE member_id = @member_id_a AND coupon_id = @test_coupon_id
ORDER BY member_coupon_id;
-- 2건, coupon_status='ISSUED', expires_at = issued_at + 7일(coupon.valid_days) 확인
```

확인 기준:
- `challenge_progress.reward_claimed_at`이 `NULL`에서 실제 시각으로 바뀜
- `member_coupon`에 정확히 2건 생성(§3에서 등록한 `reward_quantity=2`만큼)
- 각 행의 `coupon_status='ISSUED'`, `expires_at`이 `issued_at`보다 정확히 7일 뒤(§1에서 `valid_days=7`로 넣었으므로)
- `point_history`에는 새 행이 안 생겼어야 함(이 챌린지 보상은 coupon만 있으므로 `grantedPoint=0`과 일치)
