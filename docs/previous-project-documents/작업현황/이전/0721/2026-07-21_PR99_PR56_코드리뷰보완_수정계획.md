### 1.1 A-003 리뷰 탭 결정 근거

- `docs/API 명세/api-spec(final).md`의 `API-ADMIN-MEMBER-002`는 대여·결제·신고·포인트·제재 탭을 정의하며 리뷰 탭을 정의하지 않는다.
- `docs/작업현황/설계문서/2026-07-16_관리자-회원API_설계문서.md`도 `RENTALS`, `PAYMENTS`, `REPORTS`, `POINTS`, `SANCTIONS`만 탭 계약으로 정한다.
- PR #99 이전 A-003의 리뷰 탭은 `reviewHistories` fallback 더미 배열을 표시하던 구조였고, 실제 API 응답으로 연결된 기능이 아니었다.
- 따라서 fixture SQL에 리뷰 데이터를 추가해도 A-003에서 표시할 응답 계약이 생기지 않는다. 리뷰 탭이 향후 필수 요구가 되면 별도 API 설계·백엔드 구현·프론트 연결 작업으로 분리한다.

## 4. 프론트 저장소 수정 계획

대상 저장소: `C:\Github\abc-proj-win-FRONT\abc_front`

### 4.1 `API-COLLECTION-002` 실제 연결

대상 파일:

- `src/pages/user/U001Home/HomePage.tsx`
- `src/pages/user/U006Books/BooksPage.tsx`
- `src/api/collectionApi.ts` 및 `src/types/api.ts`는 기존 wrapper·타입을 재사용한다.

작업:

1. U-001의 현재 컬렉션 더보기 링크에 선택된 컬렉션의 `collectionId`를 query string으로 전달한다.
2. U-006에서 `section=collection`과 `collectionId`를 읽는다.
3. U-006의 기존 섹션형 도서 목록 렌더링 분기 안에서 `getCollectionDetail(collectionId)`를 호출한다.
4. 응답의 `collectionName`과 `books`를 기존 제목·도서 목록 상태에 대입한다.
5. `collectionId`가 없거나 숫자가 아니면 상세 API를 호출하지 않고 기존 오류/빈 상태 처리로 안내한다.

제약:

- 새 route, 페이지, 카드, 섹션, CSS, 클래스명, 스타일 속성은 만들거나 바꾸지 않는다.
- U-001의 동적 컬렉션 섹션은 프론트 설계 문서가 요구한 영역이므로 유지한다. 다만 이전 연결계획의 JSX 구조 변경 제외 범위를 넘은 변경이므로, 이 문서로 범위 확장을 기록한다.

### 4.2 A-013 포인트 잔액·실패 처리 정정

대상 파일:

- `src/pages/admin/A013CouponsPoints/AdminCouponsPointsPage.tsx`
- 필요 시 `src/api/adminMemberApi.ts`의 기존 `getAdminMember()`과 `adjustAdminMemberPoint()` 반환 타입을 재사용한다.

작업:

1. `getAdminMembers()` 목록 응답에는 잔액이 없으므로, 회원 선택 시 `getAdminMember(memberId)`를 호출해 `usageSummary.pointBalance`를 읽는다.
2. 실제 잔액을 조회하기 전에는 임의의 `0`을 현재 잔액으로 저장·검증·표시하지 않는다.
3. 차감 전 프론트 검증은 조회한 실제 잔액을 이용한 UX 보조 검증으로만 유지한다.
4. `adjustAdminMemberPoint()` 성공 시 응답의 `pointBalance`와 `pointHistoryId`를 사용해 선택 회원 상태와 최근 이력을 갱신하거나, 필요한 데이터만 재조회한다.
5. 요청 실패 시 성공 메시지, 로컬 잔액 변경, 가짜 이력 추가를 하지 않고 서버 오류 메시지만 표시한다.
6. 서버의 음수 잔액 검증과 `requestId` 멱등 처리는 변경하지 않는다.

근거: 백엔드는 회원 잠금 후 실제 잔액으로 음수 여부를 검증하고, `API-ADMIN-MEMBER-004` 응답에 조정 직후 `pointBalance`를 제공한다. 이 항목은 DB 또는 Java 수정이 아닌 프론트의 잘못된 임시 상태 처리 문제다.
