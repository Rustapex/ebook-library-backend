## 2. 현재 문제

`handleSelectMember()`는 `getAdminMember()`로 선택 회원의 실제 잔액만 조회한다. 이미 존재하는 `getAdminMemberPoints(memberId)`를 호출하지 않아 `pointHistories`가 fallback 이력 또는 이전 선택 회원의 이력을 유지할 수 있다.

따라서 회원 A를 선택한 후 B를 선택하면 B의 최근 조정 이력 자리에 A 또는 fallback 이력이 표시될 수 있다. B의 포인트 조정 성공 후에도 새 이력이 기존 잘못된 목록에 섞일 수 있다.

## 3. 프론트 수정 계획

### 3.1 선택 시 상세·포인트 이력 동시 조회

1. `getAdminMember()`와 `getAdminMemberPoints()`를 선택한 `memberId`로 함께 요청한다. 두 요청은 `Promise.allSettled()` 또는 동등한 개별 실패 처리로 실행한다.
2. 새 회원 선택을 시작하는 즉시 `selectedMember = null`, `pointHistories = []`, `pointHistoryError = ''`, `isPointHistoryLoading = true`로 초기화한다.
3. 두 요청 결과를 받은 뒤 DEFAULT 상세 성공 여부를 먼저 판정한다.
4. DEFAULT 상세 조회가 실패하면 POINTS 요청이 성공했어도 이력 결과를 반영하지 않는다. 선택 회원을 설정하지 않고 포인트 조정도 진행할 수 없게 기본 오류만 표시한다.
5. DEFAULT 상세 조회가 성공하면 `usageSummary.pointBalance`로 선택 회원과 목록의 해당 행 잔액을 갱신한다.
6. DEFAULT 성공 및 POINTS 성공인 경우에만 `pointsResponse.memberId === 요청한 memberId`를 확인한 뒤 `pointsResponse.tab.content`를 `pointHistories`에 대입한다.
7. DEFAULT 성공이지만 POINTS 조회가 실패하거나 응답 `memberId`가 다르면 실제 잔액을 유지하고 포인트 조정도 허용한다. 이력은 빈 배열로 유지하고, "포인트 이력을 불러오지 못했습니다" 이력 전용 오류 상태를 표시한다. 이전 회원·fallback 이력을 재사용하지 않는다.

### 3.2 이력 전용 상태와 렌더링

1. `formError`와 별도로 `pointHistoryError`, `isPointHistoryLoading`을 둔다.
2. 최근 조정 이력 영역은 아래 네 상태를 명확히 렌더링한다.
   - 조회 중: 로딩 안내
   - 조회 성공 + 빈 목록: 이력 없음 안내
   - 조회 실패: 빈 목록과 이력 전용 오류
   - 조회 성공 + 목록 존재: 선택 회원의 이력 목록
3. `fallbackPointHistories`는 빈 배열로 전환하거나 제거한다. fallback 또는 이전 회원 이력이 실제 이력처럼 표시되면 안 된다.

### 3.3 빠른 연속 선택과 조정 응답 보호

1. `selectionRequestSequenceRef`와 `pointHistoryRequestSequenceRef`를 각각 `useRef`로 둔다.
2. 회원 선택을 시작할 때 `selectionRequestSequenceRef`를 증가시키고, 최초 POINTS 조회와 포인트 조정 성공 뒤 POINTS 재조회를 시작할 때마다 `pointHistoryRequestSequenceRef`를 증가시킨다.
3. 상세 조회의 성공·실패 상태 변경은 현재 selection sequence와 `memberId`가 일치할 때만 반영한다.
4. POINTS 조회·재조회 성공, 실패, loading 해제는 현재 selection sequence, `memberId`, history sequence가 모두 일치할 때만 반영한다.
5. A 선택 뒤 B를 선택한 경우, 늦게 도착한 A의 상세·이력 응답과 오류·loading 해제는 모두 무시한다.
6. 같은 회원 A에서도 최초 POINTS 조회보다 조정 후 재조회가 먼저 끝난 경우, 늦게 도착한 최초 조회 응답은 이전 history sequence이므로 무시한다.
7. 포인트 조정 중에는 회원 선택을 비활성화한다. 조정 응답도 요청을 보낸 회원이 아직 선택된 경우에만 선택 카드·이력·성공 메시지를 갱신한다.
8. 회원 변경 중에는 최근 조정 이력이 다른 회원의 값으로 잠시 표시되지 않는다.

### 3.4 포인트 조정 성공 후 이력 동기화

1. 포인트 조정 성공 후 응답의 잔액으로 선택 회원과 조회 완료 목록 행을 갱신한다.
2. 성공 응답의 일부 필드로 임시 이력을 조합하지 않는다.
3. 같은 선택 회원의 `getAdminMemberPoints(memberId)`를 다시 호출해 서버의 최신 이력 목록으로 교체한다.
4. 재조회 중에는 이력 전용 loading 상태를 표시한다.
5. 재조회가 실패하면 서버 성공값인 `pointBalance`는 유지한다. 이전/fallback 이력을 복구하지 않고 빈 이력과 이력 전용 오류를 표시한다.
6. 재조회 성공·실패·loading 해제도 현재 selection sequence, `memberId`, history sequence가 모두 일치할 때만 반영한다.

## 4. 완료 기준

| 확인 항목 | 완료 기준 |
|---|---|
| 회원 A 선택 | A의 실제 잔액과 A의 포인트 이력만 표시한다. |
| 회원 B 전환 | A/fallback 이력을 즉시 제거하고 B의 이력만 표시한다. |
| 빠른 A → B 전환 | 늦은 A 응답이 B의 잔액·이력·오류 상태를 덮어쓰지 않는다. |
| 같은 회원 이력 경합 | A의 최초 POINTS 조회가 늦어도 조정 성공 뒤 최신 POINTS 재조회 결과를 덮어쓰지 않는다. |
| DEFAULT 실패 | POINTS 요청이 성공했어도 이력·선택 회원 상태에 반영하지 않는다. |
| POINTS 응답 검증 | 응답 `memberId`가 요청 `memberId`와 일치할 때만 `tab.content`를 표시한다. |
| 이력 조회 실패 | 빈 이력과 명시적 오류만 표시하며, 이전 이력을 보이지 않는다. |
| 이력 영역 상태 | 조회 중, 이력 없음, 조회 실패, 이력 목록의 네 상태가 `formError`와 분리되어 표시된다. |
| 조정 중 회원 전환 | 회원 선택이 비활성화되며, 조정 응답이 다른 회원의 상태를 갱신하지 않는다. |
| 조정 성공 | 선택 회원의 서버 성공 잔액을 유지하고, 이력 재조회 성공 시 최신 이력으로 교체한다. 재조회 실패 시 빈 이력과 이력 전용 오류를 표시한다. |
| 조정 실패 | 성공 메시지·가짜 이력·로컬 잔액 변경이 발생하지 않는다. |
| 정적 검증 | `npm run build`가 성공한다. |
| 수동 확인 | 관리자 계정으로 A-013에서 회원 전환·조정 성공·실패 경로를 확인한다. |

## 5. 작업 순서

1. A-013의 `pointHistories` 초기값, 선택 핸들러, 최근 조정 이력 렌더링 경로를 확인한다.
2. 선택 시 초기화, DEFAULT 우선 판정, POINTS 응답 `memberId` 검증, 이력 전용 상태를 구현한다.
3. selection/history 이중 sequence 보호와 포인트 조정 중 회원 선택 비활성화를 구현한다.
4. 포인트 조정 성공 뒤 이력 재조회 경로를 추가한다.
5. 회원 전환·같은 회원 이력 경합·DEFAULT 실패·이력 조회 실패·조정 성공/실패·재조회 실패를 정적 검토한다.
6. `npm run build`와 관리자 화면 수동 확인을 수행한다.
