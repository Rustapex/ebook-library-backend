# Docker 객관식 문제 20선

각 문항에서 가장 알맞은 답 하나를 고르세요.

1. Docker 이미지와 컨테이너의 관계를 가장 정확히 설명한 것은 무엇인가?
   - ① 이미지는 실행 중인 프로세스이고 컨테이너는 읽기 전용 템플릿이다.
   - ② 이미지는 실행 환경을 포함한 불변 템플릿이며, 컨테이너는 그 이미지의 실행 인스턴스다.
   - ③ 이미지는 반드시 하나의 컨테이너에서만 사용할 수 있다.
   - ④ 컨테이너를 삭제해도 컨테이너 내부의 모든 데이터는 자동으로 이미지에 저장된다.

2. 다음 Dockerfile에서 `COPY requirements.txt .`와 `RUN pip install -r requirements.txt`를 애플리케이션 전체 복사보다 먼저 두는 주된 이유는 무엇인가?
   - ① 의존성 설치 결과 레이어를 소스 코드 변경 시 재사용하기 위해
   - ② 컨테이너의 포트를 자동으로 외부에 공개하기 위해
   - ③ 컨테이너를 항상 root 사용자로 실행하기 위해
   - ④ 볼륨을 자동으로 생성하기 위해

3. Dockerfile의 `WORKDIR /app`이 수행하는 작업으로 가장 적절한 것은 무엇인가?
   - ① 호스트의 `/app` 디렉터리를 삭제한다.
   - ② 이후 명령이 실행될 컨테이너 내부 기본 작업 디렉터리를 설정한다.
   - ③ 컨테이너의 외부 포트를 8080으로 설정한다.
   - ④ 이미지를 레지스트리에 업로드한다.

4. `CMD`와 `ENTRYPOINT`에 대한 설명으로 가장 적절한 것은 무엇인가?
   - ① 둘 다 이미지를 빌드할 때만 실행되고 컨테이너 실행에는 영향이 없다.
   - ② `CMD`는 기본 실행 명령 또는 인자를 제공하고, `ENTRYPOINT`는 컨테이너의 주 실행 파일을 고정하는 데 주로 사용한다.
   - ③ `ENTRYPOINT`는 Docker Compose에서만 사용할 수 있다.
   - ④ `CMD`는 볼륨을 생성하는 명령이다.

5. Dockerfile의 `EXPOSE 8080`에 대한 설명으로 옳은 것은 무엇인가?
   - ① 호스트의 8080 포트를 자동으로 컨테이너에 연결한다.
   - ② 컨테이너가 사용할 포트 정보를 문서화하며, 외부 공개는 실행 시 포트 매핑으로 별도 설정할 수 있다.
   - ③ 컨테이너 내부에서 8080 포트를 차단한다.
   - ④ 해당 이미지의 모든 네트워크 기능을 비활성화한다.

6. `docker run -p 8080:80 nginx`의 포트 매핑 설명으로 가장 정확한 것은 무엇인가?
   - ① 호스트 80 포트를 컨테이너 8080 포트에 연결한다.
   - ② 호스트 8080 포트를 컨테이너 80 포트에 연결한다.
   - ③ 컨테이너 8080 포트와 80 포트를 모두 차단한다.
   - ④ 호스트와 컨테이너에 모두 8080 포트를 새로 만든다.

7. 컨테이너를 삭제한 뒤에도 MySQL 데이터가 유지되어야 한다. 가장 적합한 방법은 무엇인가?
   - ① 데이터를 컨테이너의 쓰기 가능 레이어에만 저장한다.
   - ② 데이터 디렉터리에 named volume을 마운트한다.
   - ③ 이미지 태그를 변경한다.
   - ④ `EXPOSE 3306`만 추가한다.

8. 다음 Compose 설정에서 `db_data:/var/lib/mysql`의 주된 효과는 무엇인가?
   - ① MySQL의 데이터 디렉터리를 named volume에 저장한다.
   - ② MySQL 3306 포트를 외부에 공개한다.
   - ③ MySQL 이미지를 자동으로 빌드한다.
   - ④ 컨테이너 이름을 `db_data`로 지정한다.

9. Docker Compose에서 같은 네트워크에 연결된 `spring_app`이 `mysql_container`에 접속할 때, 일반적으로 사용할 호스트 이름으로 가장 적절한 것은 무엇인가?
   - ① `localhost`
   - ② `127.0.0.1`
   - ③ `mysql_container`
   - ④ 호스트 PC의 공인 IP

10. Compose에서 애플리케이션이 DB 서비스에 접속할 때 사용할 포트로 가장 적절한 것은 무엇인가? DB가 `ports: - "3303:3306"`으로 설정되어 있고 두 서비스가 같은 Compose 네트워크에 있다.
   - ① 3303, 호스트 포트이므로 컨테이너 간 통신에도 사용한다.
   - ② 3306, DB 컨테이너 내부 포트를 사용한다.
   - ③ 8080, 애플리케이션의 HTTP 포트를 사용한다.
   - ④ 포트는 필요 없고 이미지 이름만 쓴다.

11. Docker Compose의 `depends_on`에 대한 설명으로 가장 정확한 것은 무엇인가?
   - ① 의존 서비스의 시작 순서를 정의할 수 있다.
   - ② DB가 SQL 요청을 받을 준비가 된 것까지 항상 보장한다.
   - ③ 의존 서비스의 데이터를 자동으로 백업한다.
   - ④ 컨테이너 이미지의 용량을 줄인다.

12. DB 컨테이너가 프로세스는 시작했지만 아직 접속 가능한 상태가 아닐 수 있다. 이를 확인하기 위한 Compose 설정으로 가장 적절한 것은 무엇인가?
   - ① `healthcheck`
   - ② `container_name`
   - ③ `EXPOSE`
   - ④ `WORKDIR`

13. Compose 파일의 `networks:` 섹션을 사용하는 주된 이유는 무엇인가?
   - ① 여러 서비스가 공유할 네트워크를 정의하고 연결하기 위해
   - ② Dockerfile의 빌드 순서를 정의하기 위해
   - ③ 컨테이너 로그의 보존 기간을 정하기 위해
   - ④ 이미지 레이어를 압축하기 위해

14. 실행 중인 컨테이너의 로그를 계속 따라가며 확인하려면 어떤 명령을 사용해야 하는가?
   - ① `docker image ls -f <컨테이너ID>`
   - ② `docker logs -f <컨테이너ID>`
   - ③ `docker volume rm <컨테이너ID>`
   - ④ `docker build -f <컨테이너ID>`

15. 컨테이너가 비정상 종료됐을 때 자동 재시작 정책을 설정하려면 어떤 옵션을 사용해야 하는가?
   - ① `--restart`
   - ② `--network`
   - ③ `--expose`
   - ④ `--entrypoint`

16. 다음 중 Docker 이미지 크기를 불필요하게 키울 가능성이 가장 큰 Dockerfile 작성 방식은 무엇인가?
   - ① 의존성 목록 파일만 먼저 복사한 뒤 설치한다.
   - ② 빌드 산출물과 실행에 필요한 파일만 복사한다.
   - ③ 소스, 로컬 캐시, 테스트 결과 등 빌드에 불필요한 모든 파일을 컨텍스트에 포함한다.
   - ④ 경량 베이스 이미지를 검토한다.

17. `build: .`가 설정된 Compose 서비스에 대한 설명으로 가장 적절한 것은 무엇인가?
   - ① 현재 디렉터리를 빌드 컨텍스트로 사용해 Dockerfile 등을 바탕으로 이미지를 빌드한다.
   - ② 현재 디렉터리를 컨테이너 내부의 영구 볼륨으로 만든다.
   - ③ 현재 디렉터리의 모든 파일을 컨테이너 로그로 출력한다.
   - ④ 현재 디렉터리의 포트를 자동 탐지해 공개한다.

18. MySQL 공식 이미지에 `./db/init.sql:/docker-entrypoint-initdb.d/init.sql`을 마운트했는데 기존 named volume에 이미 데이터가 있다. 초기화 SQL이 다시 실행되지 않을 수 있는 가장 타당한 이유는 무엇인가?
   - ① 초기화 스크립트는 일반적으로 데이터 디렉터리가 처음 초기화될 때만 실행되기 때문이다.
   - ② `init.sql`은 반드시 Dockerfile의 `CMD`로만 실행할 수 있기 때문이다.
   - ③ named volume은 읽기 전용이기 때문이다.
   - ④ MySQL 이미지는 SQL 파일을 지원하지 않기 때문이다.

19. 컨테이너 내부 애플리케이션 설정에서 DB 주소를 `localhost`로 지정했을 때 흔히 발생하는 문제는 무엇인가?
   - ① `localhost`는 애플리케이션 컨테이너 자신을 가리키므로 별도 DB 컨테이너에 연결되지 않는다.
   - ② `localhost`는 항상 호스트 PC의 DB를 가리킨다.
   - ③ Docker가 모든 네트워크를 자동으로 삭제한다.
   - ④ Dockerfile이 실행되지 않는다.

20. 다음 요구 사항을 모두 만족하는 구성이 가장 적절한 것은 무엇인가? “Spring 애플리케이션과 MySQL은 함께 기동되고, DB 데이터는 유지되며, 애플리케이션은 서비스 이름으로 DB에 연결해야 한다.”
   - ① Compose에서 두 서비스를 정의하고, DB 데이터 디렉터리에 named volume을 마운트하며, 같은 네트워크에서 DB 서비스 이름을 JDBC 호스트로 사용한다.
   - ② Spring과 MySQL을 하나의 컨테이너에 설치하고 모든 데이터를 컨테이너 내부에만 저장한다.
   - ③ MySQL 포트만 `EXPOSE`하고 애플리케이션에는 DB 주소를 지정하지 않는다.
   - ④ DB 컨테이너를 매번 새로 만들고 컨테이너의 쓰기 가능 레이어에만 데이터를 저장한다.
