# Docker 이해 확인 객관식 20문제

각 문항에서 가장 알맞은 답 하나를 고르세요.

## 1. Docker 이미지(Image)는 무엇인가?

- ① 실행 중인 컨테이너
- ② 애플리케이션 실행 환경을 담은 읽기 전용 템플릿
- ③ 데이터베이스만 저장하는 공간
- ④ 컨테이너 로그 파일

## 2. Docker 컨테이너(Container)는 무엇인가?

- ① 이미지를 실행한 상태
- ② 이미지를 만드는 설정 파일
- ③ Docker Hub 계정
- ④ 호스트 운영체제

## 3. 이미지와 컨테이너의 관계로 알맞은 것은 무엇인가?

- ① 컨테이너는 이미지를 실행해서 만들어진다.
- ② 이미지는 컨테이너를 실행해서 만들어진다.
- ③ 이미지와 컨테이너는 같은 말이다.
- ④ 컨테이너는 이미지 없이 실행된다.

## 4. Dockerfile은 무엇을 위한 파일인가?

- ① Docker 이미지를 만드는 설정 파일
- ② 컨테이너 로그를 보는 파일
- ③ 데이터베이스 데이터를 저장하는 파일
- ④ Docker를 삭제하는 파일

## 5. Dockerfile의 `FROM`은 무엇을 지정하는가?

- ① 시작할 기본 이미지
- ② 컨테이너 이름
- ③ 외부 공개 포트
- ④ 볼륨 이름

## 6. Dockerfile의 `WORKDIR /app`은 무엇을 하는가?

- ① 컨테이너 내부 작업 폴더를 `/app`으로 설정한다.
- ② 호스트 PC의 `/app` 폴더를 삭제한다.
- ③ 8080 포트를 연다.
- ④ 이미지를 실행한다.

## 7. Dockerfile의 `COPY . .`는 무엇을 하는가?

- ① 현재 파일들을 이미지 안으로 복사한다.
- ② 컨테이너를 삭제한다.
- ③ 데이터베이스를 생성한다.
- ④ 포트를 외부에 공개한다.

## 8. Dockerfile의 `RUN`은 주로 언제 사용되는가?

- ① 이미지 빌드 중 필요한 명령을 실행할 때
- ② 컨테이너 로그를 실시간으로 볼 때
- ③ 네트워크를 삭제할 때
- ④ 컨테이너 이름을 정할 때

## 9. Dockerfile의 `CMD` 또는 `ENTRYPOINT`는 무엇을 지정하는가?

- ① 컨테이너가 시작될 때 실행할 명령
- ② 이미지의 저장 위치
- ③ 볼륨의 이름
- ④ 호스트 PC의 IP 주소

## 10. Dockerfile의 `EXPOSE 8080`은 무엇을 의미하는가?

- ① 애플리케이션이 사용할 포트가 8080임을 표시한다.
- ② 컨테이너를 8080개 생성한다.
- ③ DB 데이터를 8080에 저장한다.
- ④ 컨테이너를 자동 재시작한다.

## 11. Docker Volume을 사용하는 가장 중요한 이유는 무엇인가?

- ① 컨테이너가 삭제되어도 데이터를 유지하기 위해
- ② 이미지를 더 크게 만들기 위해
- ③ 로그를 삭제하기 위해
- ④ 컨테이너 이름을 바꾸기 위해

## 12. MySQL 데이터를 유지하려면 일반적으로 어디에 볼륨을 연결하는가?

- ① MySQL 데이터 디렉터리
- ② Dockerfile의 첫 줄
- ③ 컨테이너 이름
- ④ 이미지 태그

## 13. Docker Compose는 무엇을 위한 도구인가?

- ① 여러 컨테이너를 함께 정의하고 실행·관리하는 도구
- ② Docker를 설치하는 도구
- ③ 이미지 파일을 편집하는 도구
- ④ 로그만 보는 도구

## 14. Compose 파일에서 `services:`는 무엇을 정의하는가?

- ① 실행할 컨테이너 서비스들
- ② 이미지의 용량
- ③ 로그 파일의 이름
- ④ 운영체제 버전

## 15. Compose의 `networks:`는 왜 사용하는가?

- ① 컨테이너들이 서로 통신할 네트워크를 만들기 위해
- ② Dockerfile을 빌드하기 위해
- ③ 이미지를 삭제하기 위해
- ④ 컨테이너를 재시작하기 위해

## 16. Compose에서 `depends_on`은 무엇을 설정하는가?

- ① 서비스의 시작 순서
- ② 이미지의 크기
- ③ 데이터베이스 비밀번호
- ④ 로그 출력 형식

## 17. 컨테이너가 종료되었을 때 자동으로 다시 시작하도록 하는 옵션은 무엇인가?

- ① `--restart`
- ② `--volume`
- ③ `--copy`
- ④ `--logs`

## 18. 컨테이너 로그를 실시간으로 보려면 어떤 명령을 사용하는가?

- ① `docker logs -f <컨테이너ID>`
- ② `docker image ls`
- ③ `docker volume rm`
- ④ `docker build`

## 19. Spring Boot 컨테이너와 MySQL 컨테이너가 같은 Compose 네트워크에 있을 때, Spring Boot는 보통 무엇으로 MySQL에 접속하는가?

- ① MySQL 서비스 또는 컨테이너 이름
- ② 항상 `localhost`
- ③ 호스트 PC의 바탕화면 경로
- ④ Dockerfile 이름

## 20. Spring Boot와 MySQL을 Compose로 함께 실행할 때 가장 알맞은 구성은 무엇인가?

- ① Spring Boot와 MySQL 서비스를 정의하고, MySQL에는 볼륨을 연결한다.
- ② Spring Boot와 MySQL을 모두 삭제한다.
- ③ MySQL 데이터를 컨테이너 내부에만 저장한다.
- ④ Dockerfile 없이 로그만 실행한다.
