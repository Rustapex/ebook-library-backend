## 확정 계약표(향후 문서 반영 시 그대로 사용)

| API ID | Method / URL | 확정 역할 |
|---|---|---|
| API-ADMIN-BOOK-001 | GET /api/v1/admin/books | 목록 조회, HIDDEN/INACTIVE 포함 |
| API-ADMIN-BOOK-002 | POST /api/v1/admin/books | 등록, 항상 INACTIVE 생성 |
| API-ADMIN-BOOK-003 | PUT /api/v1/admin/books/{bookId} | 허용 메타정보 전체 교체(전자책 원문·페이지·키워드·파일·집계값 보존) |
| API-ADMIN-BOOK-004 | PATCH /api/v1/admin/books/{bookId}/status | 상태 변경. 동일 상태는 사유 없이 200 no-op(상태·감사 로그 불변). 실제 변경 시에만 `reason` 필수(trim 후 공백이면 400) |
| API-ADMIN-BOOK-005(신규) | GET /api/v1/admin/books/{bookId} | 관리자 상세 조회, ADMIN 전용, 비공개 상태 포함, read-only(감사 로그 없음) |

## 반영 대상별 변경 예정 내용

### `docs/API 명세/api-spec(final).md`

- API 목록 요약 표(관리자 도서 구간)에 005 신규 행 추가: `GET /api/v1/admin/books/{bookId}`, 권한 관리자, 화면 A-006, 관련 Entity `BOOK, BOOK_DETAIL, BOOK_AUTHOR, AUTHOR, BOOK_CATEGORY, CATEGORY, PUBLISHER`.
- 002/003 관련 Entity 목록에서 `BOOK_FILE`, `BOOK_PAGE`, `BOOK_KEYWORD`, `BOOK_KEYWORD_MAP`을 제거한다(이 API들은 원문·페이지·키워드를 다루지 않음).
- 4.6절 상세 계약 표:
  - 002 Body에서 `keywords[]`, `status`, `detail`(전체 필드), `file`, `pages[]`를 `authors[]`, `categoryIds[]?`, `detail?{description?, tableOfContents?, publisherReview?}`로 정정하고, "status는 요청으로 받지 않으며 신규 도서는 항상 INACTIVE로 생성" 문구를 추가한다.
  - 003 Body를 "등록과 동일한 허용 메타정보 필드(전체 교체, status 제외)"로 정정하고, "실 열람 원문·페이지·키워드·파일·집계값은 어떤 경우에도 변경하지 않음" 문구를 추가한다. Response에 `status`를 추가한다(`bookId`, `status`, `updatedAt`).
  - 004 설명에 "요청 상태가 현재 상태와 같으면 사유 없이 200 no-op(상태·감사 로그 불변). 실제 상태 변경일 때만 reason이 필수(공백만이면 400)"를 추가한다.
  - 005 신규 행 추가: Path `bookId`, Response `bookId, title, isbn, publisherName, authors[]{authorId,authorName,status}, categories[]{categoryId,categoryName,status}, rentalType, rentalPrice, defaultRentalDays, coverImageUrl, detail{description,tableOfContents,publisherReview}, status, createdAt, updatedAt`. 정책: "AVAILABLE/HIDDEN/INACTIVE 모두 조회 가능. 없는 도서는 404. 현재 연결된 작가·카테고리는 비활성이어도 status와 함께 노출. BookPage·detailContent·키워드·파일·집계값은 응답에 없음. read-only이므로 감사 로그 없음."

### `docs/화면흐름도/03-Admin-상세화면설계도.md`

- A-005(도서 등록) 입력 구역 표에서 "분류"를 "카테고리(기존 ACTIVE 카테고리만 선택 가능)"로, "표시"에서 상태 항목을 제거(등록은 항상 INACTIVE), "상세"를 "책 소개, 목차, 출판사 리뷰"로, "전자책 본문" 행을 삭제한다. 버튼 표에서 `페이지 추가`를 삭제한다.
- A-005 하단 설명에 "장르 키워드·해시태그·전자책 본문(페이지)·파일 업로드는 이 화면에서 다루지 않는다" 문구를 추가한다.
- A-006(도서 수정) 서두에 "초기 데이터는 API-ADMIN-BOOK-005(관리자 도서 상세 조회)로 조회한다"를 명시하고, 연동 API를 `API-ADMIN-BOOK-003~004`에서 `API-ADMIN-BOOK-003~005`로 확장한다.
- A-006 상태 변경 버튼 설명에 "동일 상태 재저장은 사유 없이 처리(no-op)"를 추가한다.

## 실제 스키마/코드 불변 사실

- `src/main/resources/schema.sql`은 이번 대응과 무관하게 변경하지 않는다. `book`/`book_detail`/`book_author`/`book_category` 기존 구조로 충분하다.
- `ErrorCode`는 추가하지 않는다. `CONCURRENT_UPDATE`는 이미 존재하며(관리자 회원 API에서 선반영), `BOOK_NOT_FOUND`/`CATEGORY_NOT_FOUND`/`VALIDATION_ERROR`만으로 이번 대응이 충분하다.
