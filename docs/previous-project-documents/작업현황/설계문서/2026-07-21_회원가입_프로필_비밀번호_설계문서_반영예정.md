# 회원가입·프로필·비밀번호 설계문서 반영 예정

작성일: 2026-07-21  
대상: `API-AUTH-001`, `API-ME-002`, `API-ME-003`, 화면 `U-002`, `U-015`  
상태: 설계 원본은 수정하지 않고, 구현과의 차이만 기록

## 1. 반영 배경

사용성·보안 버그 대응으로 가입 성별의 선택 안 함을 제거하고, 가입 이후 성별 변경과 동일 비밀번호 재설정을 차단한다. 이 문서는 실제 API 명세·화면설계 원본을 변경하지 않는다.

## 2. API 명세 반영 예정

### `API-AUTH-001 POST /api/v1/auth/signup`

- 기존: `gender?` 선택값
- 변경 예정: `gender`는 필수이며 `MALE`, `FEMALE`만 허용
- `NONE`, 누락, 빈 문자열, 그 밖의 값은 `400 + VALIDATION_ERROR`
- `email`은 완성된 형식이 아니면 `400 + VALIDATION_ERROR`

### `API-ME-002 PATCH /api/v1/me`

- 기존: 수정 가능 필드에 `gender` 포함
- 변경 예정: 수정 가능 필드는 `name`, `email`, `phone`만 제공
- `gender`가 요청에 포함되면 `400 + VALIDATION_ERROR`; 기존 성별은 보존

### `API-ME-003 PATCH /api/v1/me/password`

- 기존: 현재 비밀번호 일치 및 새 비밀번호 확인 일치 후 변경
- 변경 예정: 새 비밀번호가 현재 비밀번호와 같으면 `400 + VALIDATION_ERROR`로 거부
- 현재 비밀번호 불일치 응답 `AUTH_INVALID_PASSWORD`는 유지

## 3. 화면 설계 반영 예정

### `U-002` 회원가입

- 성별 선택에서 선택 안 함 항목을 제거한다.
- 성별을 선택하지 않으면 가입 요청을 보내지 않고, 서버 응답을 직접 처리하는 경우에도 `VALIDATION_ERROR`를 표시한다.
- 이메일 입력은 프런트에서 형식을 즉시 안내하되, 최종 차단 기준은 백엔드 검증이다.

### `U-015` 회원정보 수정·비밀번호 변경

- 성별은 조회 전용으로 표시하고 수정 컨트롤을 제공하지 않는다.
- 프로필 수정 요청 본문에서 `gender`를 보내지 않는다.
- 새 비밀번호가 기존 비밀번호와 같은 경우 서버의 `VALIDATION_ERROR`를 사용자에게 안내한다.

## 4. DB·프런트 문서 반영 예정

- `MEMBER.gender`와 `MEMBER.password_hash`의 스키마는 변경하지 않는다.
- 프런트 저장소의 API 타입·요청 DTO·화면 문서는 구현 완료 후 위 계약에 맞게 갱신한다.

## 5. 범위 제외

- 소장(`OWNED`) 상태·대여 가능 일수 표시는 다른 팀원 작업이므로 이 문서의 설계 차이에 포함하지 않는다.
