# 회원가입/회원정보 수정 설계문서 반영 예정

작성일: 2026-07-14
대상: `API-AUTH-001`, `API-ME-001`, `API-ME-002`, 화면 `U-002`, `U-015`
상태: 실제 설계문서 원문은 수정하지 않고, 나중에 반영할 변경 사항만 기록한다.

## 1. 반영 배경

회원가입은 이미 아이디/이메일 중복을 서비스 계층에서 차단하고 있지만, 테스트와 문서 기준에서는 공통 JSON 에러 응답까지 명확히 확인해야 한다.

회원정보 수정 화면은 진입 시 기존 정보가 채워져 있어야 한다. 프론트 문서 기준 `GET /api/v1/me`, `PATCH /api/v1/me`는 백엔드 미구현으로 표시되어 있으므로 구현 후 문서 갱신이 필요하다.

## 2. API 명세 반영 예정

### `API-AUTH-001 POST /api/v1/auth/signup`

- `loginId` 중복 시 회원가입 실패
- HTTP Status: `409 Conflict`
- JSON 응답:

```json
{
  "success": false,
  "code": "MEMBER_LOGIN_ID_DUPLICATED",
  "message": "이미 사용 중인 아이디입니다.",
  "errors": []
}
```

- `email` 중복 시 `MEMBER_EMAIL_DUPLICATED`도 같은 구조로 응답
- 신규 회원가입 성공 시 `201 Created`와 공통 성공 응답 사용

### `API-ME-001 GET /api/v1/me`

- `U-015` 회원정보 수정 화면 진입 전 기존 정보 조회용으로 사용
- 회원 JWT 필요
- 로그인 회원 본인의 정보만 조회
- 응답에는 최소한 `loginId`, `name`, `email`, `phone`, `birthDate`, `gender`, `role`, `status` 포함

### `API-ME-002 PATCH /api/v1/me`

- 회원 JWT 필요
- 수정 가능 필드: `name`, `email`, `phone`, `gender`
- 수정 불가 필드: `loginId`, `birthDate`, `role`, `status`, `memberId`, `gradeId`, `pointBalance`
- 이메일 중복 시 `409 + MEMBER_EMAIL_DUPLICATED`

## 3. 화면 설계 반영 예정

### `U-002` 회원가입

- 가입 제출 시 loginId 중복이면 API 에러 메시지를 폼에 표시한다.
- 별도 아이디 중복 확인 API는 추가하지 않는다.
- `API-AUTH-001` 응답의 `code`와 `message`를 기준으로 사용자에게 안내한다.

### `U-015` 회원정보 수정

- 화면 진입 시 `GET /api/v1/me`를 먼저 호출해 기존 정보를 채운다.
- `loginId`, `birthDate`는 읽기 전용으로 표시한다.
- `name`, `email`, `phone`, `gender`만 수정 가능하게 둔다.
- 저장 버튼은 `PATCH /api/v1/me`를 호출한다.

- `API-ME-001` 응답에 마이페이지 요약 카운트까지 포함할지, 회원정보 수정 화면용 기본 정보로 먼저 좁힐지 결정 필요
- `PATCH /api/v1/me`에서 null/누락 필드 처리 방식 결정 필요
- `phone` 빈 문자열 정규화 방식 결정 필요
