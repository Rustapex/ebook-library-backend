## 실제 SQL/스키마 불변 사실

- `src/main/resources/schema.sql`은 이번 계약 정리와 무관하게 변경하지 않는다. `collection`/`collection_book` 기존 구조로 충분하다.
- ERD/멘토링 기획 문서는 설계 의도 참고용이며, 위 계약 정리의 근거 문서로 쓰지 않는다.

## 이번 라운드에서 실제로 수정한 것(코드/사이드카 SQL만)

- `AdminCollectionService` 4개 쓰기 메서드에 `@Transactional` 추가(HIGH-1).
- `AdminCollectionPatchRequest.removeBookIds`를 `List<@NotNull @Positive Long>`로 변경 + Service 방어 검증 추가(MEDIUM).
- `AdminCollectionTransactionIntegrationTest` 신규(실제 Spring 프록시+MySQL로 lock 경로 커밋과 감사 로그 실패 시 rollback 증명).
- **범위 밖에서 발견한 별개 문제**: 로컬 DB의 `chk_admin_audit_log_action_type`/`chk_admin_audit_log_target_type`(PR #46 후속에서 수동 적용한 sidecar CHECK, `src/main/resources/관리자감사로그_CHECK제약.sql`)이 PR #50 이전 라운드에서 추가한 `COLLECTION_CREATE`/`COLLECTION_UPDATE`/`COLLECTION_BOOKS_UPDATE`/`COLLECTION_PATCH`/`COLLECTION` enum 값을 포함하지 않아, `AdminCollectionTransactionIntegrationTest`의 감사 로그 INSERT가 전부 CHECK 위반으로 실패했다. 이 sidecar SQL 파일을 새 enum 값 포함하도록 갱신하고 로컬 DB에도 재적용했다. **팀 공유 DB를 쓰는 다른 팀원은 이 갱신된 SQL을 각자 DB에 재적용해야 같은 실패를 피할 수 있다** — PR 코멘트에 명시한다.
