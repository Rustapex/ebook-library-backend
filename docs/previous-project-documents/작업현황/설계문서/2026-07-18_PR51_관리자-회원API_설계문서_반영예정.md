# 2026-07-18 PR51 관리자 회원 API 설계문서 반영 예정

## 1. 문서 목적

- 실제 설계 원문과 API 명세 원문을 지금 수정하지 않는다.
- PR51 코드리뷰 대응 구현이 끝난 뒤, 아래 항목을 기준 설계 문서에 한 번에 반영하기 위한 변경 목록이다.

## 2. DB 변경 적용 정책

| 대상 | 반영 예정 내용 | 이유 |
|---|---|---|
| DB 운영 절차 문서 | `schema.sql`은 기준 스키마로 보존하고, 구조 변경은 생성 순서가 있는 별도 sidecar SQL로 관리한다. | 개발 중 서버 기동만으로 공유·로컬 DB가 예고 없이 변경되지 않게 한다. |
| 신규 DB 준비 절차 | 새 개발 DB·테스트 DB·RDS는 기준 SQL 적용 후 누적 sidecar SQL을 수동으로 적용하고 검증 SELECT를 실행한다. | `ddl-auto=validate` 환경에서 엔티티가 요구하는 컬럼과 제약을 선행 적용해야 한다. |
| 기존 PR51 sidecar | `member.current_sanction_id` FK와 `point_history.request_id`, `(member_id, request_id)` UNIQUE를 적용하는 SQL의 실행 순서와 검증 쿼리를 기록한다. | 계정 정지 원인 연결과 포인트 멱등 키의 DB 보장을 명확히 한다. |
| 신규 포인트 sidecar | `point_history.balance_after INT NULL` 추가 SQL을 별도 파일로 관리한다. 기존 이력은 null을 허용하고 신규 `ADMIN_ADJUST`만 값을 기록한다. | 동일 멱등 키 재시도에 최초 조정 직후 잔액을 재현한다. |

## 3. API-ADMIN-MEMBER-003 상태·제재 설계 반영

- `ADMIN`, `WITHDRAWN`, `DEACTIVATED` 회원은 관리자 변경 보호 대상이다.
- `PATCH /api/v1/admin/members/{memberId}/status`의 직접 상태 변경에서 `status=JOINED`, `reason`을 보내고 `sanctionType`을 생략하면 관리자가 수동으로 계정 정지를 해제할 수 있다.
- 직접 JOINED 전환 시 이전 `currentSanctionId`를 해제하고, 상태 변경 감사 로그를 남긴다.
- 계정 정지 만료 자동 복구를 위한 서비스 로직은 보존하되, 현재 설계 범위에서는 `@Scheduled` 트리거를 두지 않는다.

## 4. API-ADMIN-MEMBER-004 포인트 조정 설계 반영

- 요청 본문은 `pointAmount`, `description`, UUID 형식의 필수 `requestId`로 고정한다.
- `(memberId, requestId)`는 대상 회원별 멱등 키다. 같은 키와 같은 금액·정규화 사유의 재요청은 추가 잔액 변경·포인트 이력·감사 로그를 만들지 않는다.
- 새 요청과 재시도 모두 응답 `pointBalance`는 해당 최초 조정 직후 저장한 `balanceAfter`다. 현재 회원 잔액을 재조회해 응답값으로 사용하지 않는다.
- 포인트 변경 대상은 `ADMIN`, `WITHDRAWN`, `DEACTIVATED`를 제외한다. 거부된 요청은 잔액·이력·감사 로그 모두 변경하지 않는다.

## 5. API-ADMIN-MEMBER-002 조회 계약 반영

- 탭별 응답은 모호한 `Object` 응답이 아니라 탭별 DTO 또는 명시된 oneOf 스키마로 Swagger에 표시한다.
- REPORTS 탭은 두 신고 유형을 통합 노출하되, 모든 결과를 애플리케이션 메모리에서 합쳐 페이지를 자르는 방식은 사용하지 않는다.
- 정렬 기준, 전체 건수, 페이지 경계가 DB 조회 단계에서 일관되게 보장되는 방식을 설계·명세에 적는다.

## 6. 반영 시점과 확인 항목

1. sidecar SQL이 실제 MySQL에 적용되고 `information_schema` 검증이 끝난 후 DB 운영 절차 문서를 갱신한다.
2. 003 수동 복구와 004 보호·멱등 재응답이 자동/수동 테스트를 통과한 후 API 명세·Swagger 설명을 갱신한다.
3. 스케줄러는 범위 제외 상태로 기록한다. 자동 복구가 필요해지는 별도 요구가 생길 때만 실행 주기, 중복 실행 방지, 장애 복구 정책을 새 설계로 추가한다.
