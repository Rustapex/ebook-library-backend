## 1. 확정 계약표

| API ID | Method / URL | 향후 명세 반영 내용 |
|---|---|---|
| API-ME-004 | `DELETE /api/v1/me` | ADMIN 역할은 `JOINED` 상태여도 탈퇴 불가(403 `AUTH_ACCESS_DENIED`). `READY`/`READING` 대여가 있으면 409 `MEMBER_WITHDRAWAL_RENTAL_IN_PROGRESS`. `OWNED`만 있으면 탈퇴 가능하며 대여·결제는 보존. |
| API-ADMIN-REPORT-001 | `GET /api/v1/admin/reports` | BOOK/REVIEW 통합 목록은 `created_at DESC, report_id DESC, target_type ASC`로 고정 정렬해 동일 시각·동일 숫자 ID의 행도 페이지 경계에서 중복·누락되지 않게 한다. 요청·응답 필드는 변경하지 않는다. |
| API-ADMIN-REPORT-002 | `PATCH /api/v1/admin/reports/{targetType}/{reportId}/status` | REVIEW `DONE`의 `ACCOUNT_SUSPENSION`만 허용. 제재 대상이 ADMIN/WITHDRAWN/DEACTIVATED면 403으로 전체 거부. 완료된 신고 재처리는 409 `REPORT_INVALID_STATUS_TRANSITION`. MySQL lock timeout/deadlock은 409 `CONCURRENT_UPDATE`. |

## 2. 상태·동시성 정책 반영 내용

- 탈퇴·무료 대여·유료 대여/결제는 같은 회원 행을 먼저 잠근 뒤 상태와 진행 중 대여를 검증한다. 탈퇴와 새 `READY`/`READING` 대여가 함께 남을 수 없다.
- 동일 신고는 한 요청만 상태 전이를 완료한다.
- 서로 다른 REVIEW 신고의 동일 회원 제재는 중첩을 허용한다. 회원은 `SANCTIONED`를 유지하고 마지막 유효 제재를 `currentSanction`으로 연결한다.
- 만료 제재와 신규 제재가 경합하면 회원 잠금과 현재 제재 원인 검증을 통해 새 제재를 잘못 해제하지 않는다.
- MySQL vendor error/SQLState가 `1205/HY000` 또는 `1213/40001`인 경우만 실제 잠금 충돌로 판정해 409 `CONCURRENT_UPDATE`로 변환한다. 다른 비관적 잠금·무결성 예외는 409로 오분류하지 않는다.
