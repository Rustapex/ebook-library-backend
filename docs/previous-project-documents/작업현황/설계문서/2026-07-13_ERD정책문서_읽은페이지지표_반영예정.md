# ERD 정책 문서 — "읽은 페이지 수" 지표 반영예정

## 무엇을 구체화하려는가

"읽은 페이지 수"가 주간/월간/연간/전체별 지표라는 것만 정해져 있고, 구체적인 계산 기준(어떤 컬럼을, 어떤 조건으로 집계하는지)은 문서에 없다. 실제 구현(`feature/user-reading-statistics`, `ReadingProgressRepository.sumReadPageCountByMemberAndPeriod()`)에서는 다음 기준(B1)을 채택했다.

> 조회 기간 안에 `last_read_at`이 있는 `reading_progress` 행의 `read_page_count`(해당 대여에서 지금까지 도달한 최대 페이지, 누적값)를 합산한다.

## 반영 제안

ERD 정책 문서 §3.6의 "읽은 페이지 수" 항목에 아래 각주를 추가하도록 제안한다.

> (구현 각주) 읽은 페이지 수는 페이지 조회 이벤트 로그가 아니라, 진행상황(`reading_progress`)의 `last_read_at`이 조회 기간 안에 있는 행의 누적 최대 도달 페이지(`read_page_count`) 합으로 계산하는 근사치다. 한 기간에 걸쳐 진행 중인 책은 실제로 그 기간에 읽은 페이지보다 많은 값이 잡힐 수 있다(예: 이전 기간에 읽은 페이지까지 포함). 정확한 순수 독서량이 필요해지면 별도 페이지 조회 이벤트 로그 테이블 도입을 후속 검토해야 한다.

## 반영 이유

현재 정책 문서에는 "읽은 페이지 수"라고만 적혀 있어서, 나중에 이 문서를 다시 보는 사람이 근사치라는 걸 모르고 정확한 값으로 오해할 수 있다. 계산 기준을 명시해두면 화면 설계나 다른 기능에서 이 지표를 재사용할 때 같은 오해를 반복하지 않는다.

## 처리 방식

이 문서에는 기록만 남기고, 실제 ERD 정책 문서(`docs/기획문서들/멘토링전기획문서/ERD-정책-확정-필요사항 수정후.md`) 수정은 기획팀/문서 담당자에게 넘긴다. 이 작업(백엔드 구현) 담당자는 해당 문서를 직접 수정하지 않는다.
