## 1. 확정 계약표 (api-spec(final).md 반영 예정)

| API ID | Method / URL | 반영 예정 내용 |
|---|---|---|
| API-ADMIN-RENTAL-001 | `GET /api/v1/admin/rentals` | 고정 정렬 `createdAt DESC, rentalId DESC`. 응답 필드: 대여 ID, 회원 ID·이름, 도서 ID·제목, 대여 상태, 대여·최초 열람·종료 시각, 진행률(`progression`), 결제 요약(무료 대여는 `payment=null`). 목록/count query는 같은 predicate 사용, 결제 요약은 rental id bulk 조회로 N+1 방지. |

## 2. 반영 근거 — 소스 대조 결과 (2026-07-23 확인, 전체 통독·build 없이 필요한 줄만 확인)

### 2.1 API-ADMIN-RENTAL-001 / API-ADMIN-PAYMENT-001

- `src/main/java/com/acorn/abc/rental/repository/BookRentalRepository.java` `searchForAdmin` 쿼리: `ORDER BY r.createdAt DESC, r.rentalId DESC` — 실제 구현이 구현계획 §2.3과 정확히 일치.
- `src/main/java/com/acorn/abc/payment/repository/PaymentRepository.java` `searchForAdmin` 쿼리: `ORDER BY p.paidAt DESC, p.paymentId DESC` — 실제 구현이 구현계획 §2.3과 정확히 일치.
- `src/main/java/com/acorn/abc/rental/dto/AdminRentalSummaryResponse.java`: `rentalId, memberId, memberName, bookId, bookTitle, rentalStatus, createdAt, rentalStartAt, rentalEndAt, progression, payment(nullable)` — 계획 문서 설명과 필드 구성 일치.
- `src/main/java/com/acorn/abc/payment/dto/AdminPaymentSummaryResponse.java`: `paymentId, memberId, memberName, rentalId, bookId, bookTitle, paymentMethod, originalAmount, couponDiscountAmount, pointUsedAmount, amount, paidAt` — 계획 문서 설명과 필드 구성 일치.
- `AdminRentalService`/`AdminPaymentService`가 위 `searchForAdmin` 메서드를 실제로 호출함을 확인(다른 미사용 쿼리와 혼동 없음).

### 2.2 JWT 필터 매 요청 재검증

- `git show 7d18338:.../JwtAuthenticationFilter.java`(이번 PR 이전): `memberRepository` 참조 없음. `doFilterInternal`은 `jwtTokenProvider.validateToken(token)` 통과 시 바로 `SecurityContext`를 설정 — DB 재조회 없음.
- 현재 `src/main/java/com/acorn/abc/common/security/JwtAuthenticationFilter.java:28-52`: 토큰 검증 통과 후 `isActiveMember(memberId)`가 `memberRepository.findById(memberId)`로 상태를 조회하고 `JOINED`일 때만 `SecurityContext`를 설정. `common` 패키지 전체에서 이 파일 외에 동일 기능을 하는 다른 코드는 없음(유일한 지점).
