## 1. `TOTAL` 기준일 차이 — 안 A 확정(문서만 보강)

기존 반영예정 문서(`docs/작업현황/설계문서/2026-07-12_PR42_TOTAL기준일불일치_설계문서_반영예정.md`)에서 미확정이었던 안 A/안 B 중 **안 A(현행 코드 유지, API 명세 문서만 보강)**로 확정됐다. 코드/테스트는 변경하지 않는다.

- **반영 대상**: `docs/API 명세/api-spec(final).md` — `API-ADMIN-STAT-001` 응답 필드 설명에 다음 문구 추가.
  > `periodType=TOTAL`일 때 `periodEndDate`는 항상 요청 시점의 오늘 날짜이며, 추이(`rentalTrend`/`paymentTrend`/`completedReadTrend`)와 `ageBand` 계산은 `baseDate`(생략 시 오늘) 기준으로 별도 계산된다.
- **체크리스트**:
  - [ ] `api-spec(final).md`에 위 문구 반영
  - [ ] Swagger `@Parameter` 설명과 최종 문구가 서로 어긋나지 않는지 대조

## 2. trend label 포맷 규칙 문서화

`BookRentalRepository`/`PaymentRepository`/`ReadingProgressRepository`의 native `GROUP BY` 쿼리 alias(`DATE(...)` → `yyyy-MM-dd`, `DATE_FORMAT(..., '%Y-%m')` → `yyyy-MM`)와 `AdminStatisticService.toBucketMap()`의 bucket label 문자열이 반드시 같은 포맷이어야 한다는 제약이 코드에만 있고 문서화가 안 돼 있었다(PR42 리뷰 항목).

- **반영 대상**: `docs/공통문서/백엔드_공통_개발_규칙.md`에 아래 내용을 담은 절 추가(신규 절 이름은 반영 시점에 결정).
  > 추이/집계용 native `GROUP BY` 쿼리를 추가할 때는 SQL alias 포맷(`DATE(...)`는 `yyyy-MM-dd`, `DATE_FORMAT(..., '%Y-%m')`는 `yyyy-MM`)과 서비스 계층의 bucket label 생성 로직이 반드시 같은 포맷 문자열을 써야 한다. 포맷을 바꿀 때는 해당 repository 쿼리, 서비스의 `toBucketMap()`류 매핑 로직, 관련 테스트를 함께 수정한다.
- **체크리스트**:
  - [ ] `docs/공통문서/백엔드_공통_개발_규칙.md`에 위 규칙 반영
  - [ ] 기존 3개 repository(`BookRentalRepository`/`PaymentRepository`/`ReadingProgressRepository`)의 grouped 쿼리를 예시로 링크
