# 관리자 대여·결제·신고·회원 탈퇴 API 설계 차이 기록

작성일: 2026-07-22  
대상: `API-ME-004`, `API-ADMIN-RENTAL-001`, `API-ADMIN-PAYMENT-001`, `API-ADMIN-REPORT-001`, `API-ADMIN-REPORT-002`

## 1. 기록 목적과 원문 보호

- 이 문서는 구현 계약과 프런트 데이터 연결의 차이를 추적하는 보조 기록이다.
- `docs/API 명세/api-spec(final).md`, ERD, DDL 원문은 이 작업으로 수정하지 않는다.
- 실제 API URL·권한·기본 요청/응답은 기준 API 명세를 우선한다. 프런트 코드는 후속 별도 작업에서 이 계약에 맞춘다.

## 2. 확정 구현 정책

### 2.1 회원 탈퇴와 대여

- `DELETE /api/v1/me`는 물리 삭제가 아니라 회원 상태를 `WITHDRAWN`으로 전환하고 `withdrawnAt`, 선택 `withdrawalReason`을 저장한다.
- 현재 비밀번호가 일치해야 하며 `ADMIN` 역할 계정은 탈퇴할 수 없다.
- 회원에게 `READY` 또는 `READING` 대여가 하나라도 있으면 탈퇴를 거절한다. `OWNED`는 소장 상태이므로 탈퇴를 막지 않는다.
- 탈퇴를 위해 대여 상태를 강제 종료·수정하거나 탈퇴 전용 대여 상태를 새로 만들지 않는다.
- 탈퇴 회원의 비식별화·보존 기간 정책은 이번 구현과 DB 변경에서 제외한다. 상태 전환과 접근 차단만 적용한다.

### 2.2 기존 토큰 차단

- 새 로그인 시의 회원 상태 검증은 유지한다.
- JWT 인증 필터는 토큰의 memberId로 회원 상태를 조회하고 `JOINED`일 때만 인증 객체를 만든다.
- `WITHDRAWN`, `DEACTIVATED`, `SANCTIONED` 회원은 이전에 발급받은 토큰을 사용해도 다음 보호 요청부터 401이 된다.
- Controller별 중복 검사는 추가하지 않는다. 상태 차단은 공통 인증 경계 한 곳에서 처리한다.

### 2.3 신고의 수동 처리

- 신고 대상은 `BOOK`, `REVIEW`만 허용한다.
- 상태는 `WAITING → PROCESSING/DONE/REJECTED`, `PROCESSING → DONE/REJECTED`만 허용한다. `DONE`, `REJECTED`는 이번 범위에서 재개하지 않는다.
- `hideReviewYn=true`는 `REVIEW` 신고를 `DONE`으로 처리할 때만 허용한다.
- 제재는 `REVIEW` 신고를 `DONE`으로 처리하는 관리자 수동 요청에서만 허용하며, 유형은 `ACCOUNT_SUSPENSION`만 허용한다. 사유·시작일은 필수, 종료일은 선택이다.
- 자동 리뷰 숨김, 누적 신고 수·욕설·금칙어에 따른 자동 제재, 자동 탈퇴는 구현하지 않는다.
- 신고 처리, 리뷰 숨김, 제재/회원 상태 변경, REPORT 알림, 성공 감사 로그는 하나의 transaction으로 묶고 실패 시 모두 rollback한다.

## 3. 프런트 데이터 계약 조율 기록

| 영역 | 기준 백엔드 계약 | 현재 프런트 확인 사항 | 후속 조율 방향 |
|---|---|---|---|
| 회원 탈퇴 | `DELETE /api/v1/me`, body `currentPassword`, `withdrawalReason?` | 호출 및 성공 후 로컬 토큰 제거 흐름이 존재 | 백엔드 구현 후 실제 응답/오류 표시만 대조 |
| 관리자 대여 | `q`, `memberId`, `status`, `page`, `size` | 목록 요청 wrapper·화면 존재 | 기준 파라미터와 응답 필드를 유지 |
| 관리자 결제 | `q`, `from`, `to`, `page`, `size` | 화면은 `startDate`, `endDate`를 사용 | 프런트 데이터를 `from`, `to`로 수정. 명세에 없는 `memberId` backend query는 추가하지 않음 |
| 관리자 신고 목록 | `targetType`, `status`, `page`, `size` | 화면은 추가 `q`를 보낼 수 있음 | 프런트에서 기준 외 `q` 전송을 제거하거나 별도 계약 승인 후 변경 |
| 관리자 신고 처리 | BOOK/REVIEW, 수동 상태 변경·리뷰 숨김·계정 정지 | 제재 입력 UI가 BOOK에도 표시될 수 있음 | 제재 입력은 REVIEW에서만 전송하고 BOOK에는 상태/결과만 전송 |

- 프런트 데이터 매핑 변경은 이번 백엔드 구현 PR에 넣지 않는다. 별도 PR 또는 작업 기록으로 남긴다.
- JSX, CSS, 화면 구조·배치 변경은 이 설계 기록의 범위가 아니다.

## 4. DB 및 공통 코드 적용 경계

- `MEMBER.status`, `withdrawn_at`, `withdrawal_reason`과 `BOOK_RENTAL.rental_status`의 기존 상태 제약을 사용한다. 이번 기능 때문에 대여 상태 CHECK를 변경하지 않는다.
- `SANCTION_HISTORY`, `NOTIFICATION`, `ADMIN_AUDIT_LOG`는 신고 처리 성공 transaction에만 추가된다.
- 회원의 현재 계정 정지 연결값이 필요한 환경은 프로젝트에서 관리하는 `src/main/resources` sidecar SQL 적용 상태를 전제로 한다. 기존 API 명세·ERD·기준 `schema.sql` 원문을 이 작업에서 고치지 않는다.
- ErrorCode 또는 감사 로그 enum이 필요하면 기존 값을 변경하지 않고 additive 방식으로만 추가하고, 별도 ErrorCode 기록에 근거를 남긴다.
