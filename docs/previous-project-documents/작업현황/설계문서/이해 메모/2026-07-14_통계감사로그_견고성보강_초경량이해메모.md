## 항목 1 — memberId 검증 테스트 보강 (§3.1-1)

- API: GET /api/v1/me/statistics
- 목적: 인증 principal의 memberId가 실제로 그대로 서비스/repository에 전달되는지 테스트로 직접 보장(회원 데이터 격리 계약).
- 흐름: 변경 없음(테스트만 추가) — UserStatisticControllerTest에 verify(getStatistics(eq(1L)...)), UserStatisticServiceTest에 verify(repository 호출 eq(MEMBER_ID)) 추가.
- DB: 해당 없음.
- 주의: 실제 코드 동작은 이전과 동일, 회귀 방지용 검증만 강화됨.

## 항목 2 — 감사 로그 vocabulary enum 전환 (§3.3, 안 A)

- API: GET /api/v1/admin/audit-logs 및 감사 로그를 기록하는 4개 관리자 API(포인트 조정/쿠폰 등록·발급/챌린지 수정/도서 승인)
- 목적: actionType/targetType 상수-allowlist 수동 동기화 문제를 enum 전환으로 구조적으로 해소.
- 흐름: AdminAuditLogActionType/TargetType String 상수 → enum. AdminAuditLog 엔티티 필드 @Enumerated(STRING). AdminAuditLogService가 String 쿼리 파라미터를 valueOf()로 파싱, 실패 시 BusinessException(VALIDATION_ERROR).
- DB: 스키마 변경 없음(컬럼은 계속 VARCHAR, enum 이름을 그대로 저장). 기존 데이터 호환.
- 주의: 4개 호출부(BookApprovalService/CouponService/PointService/ChallengeService)는 상수를 인라인으로만 참조해 코드 변경 불필요. 리플렉션 기반 allowlist 테스트 2개는 enum 전환으로 무의미해져 삭제.

## 항목 3 — 감사 로그 `@Schema(allowableValues)` 보강 (§3.2)

- API: GET /api/v1/admin/audit-logs
- 목적: Swagger/OpenAPI 스키마에 허용값 목록을 노출해 generated client/계약 도구에서도 값 목록을 알 수 있게 함.
- 흐름: 변경 없음(Swagger 문서화용 애너테이션만 추가) — actionType/targetType 파라미터에 @Schema(allowableValues={...}) 추가.
- DB: 해당 없음.
- 주의: 런타임 검증(안 B였던 서비스단 대조, 지금은 enum valueOf())과는 무관한 순수 문서화.

## 항목 4 — 기간·추이 계산 공통 컴포넌트 추출 (§3.1-2, 안 A)

- API: GET /api/v1/admin/statistics, GET /api/v1/me/statistics
- 목적: AdminStatisticService/UserStatisticService가 각자 들고 있던 동일한 기간(WEEKLY/MONTHLY/YEARLY/TOTAL)·추이 bucket 계산 로직 중복 제거.
- 흐름: 신규 StatisticPeriodResolver(기간 계산+fail-fast), TrendBucketCalculator(bucket 생성+granularity+toBucketMap) 컴포넌트를 두 서비스가 공통으로 주입받아 사용.
- DB: 해당 없음.
- 주의: 순수 계산 로직(외부 의존성 없음)이라 테스트에서는 mock이 아니라 실제 인스턴스를 사용(AdminStatisticServiceTest/UserStatisticServiceTest 모두 @InjectMocks 대신 수동 생성자 호출로 전환).

## 항목 5 — `reading_progress.last_read_at` 인덱스 추가 (§3.1-3)

- API: (직접 API 아님) GET /api/v1/me/statistics의 "읽은 페이지" 지표 내부 쿼리
- 목적: 회원용 독서 통계(B1, last_read_at 기간 필터) 쿼리의 range 조건 성능 보강.
- 흐름: 코드 변경 없음 — `src/main/resources/관리자통계_성능인덱스.sql`에 `CREATE INDEX idx_reading_progress_last_read_at` 한 줄 추가.
- DB: 인덱스 정의만 SQL 파일에 추가, 실제 로컬/공유 DB 적용은 이번 범위 밖(사용자가 별도 진행).
- 주의: memberId 조회 경로 자체는 이미 FK 인덱스로 커버됨을 확인 완료 — 이 인덱스는 그 안에서의 range 조건 보강용.
