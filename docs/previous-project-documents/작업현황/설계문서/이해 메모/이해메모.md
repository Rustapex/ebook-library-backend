# 회원가입·프로필·비밀번호 버그 대응 이해 메모

작성일: 2026-07-21

API: `API-AUTH-001 POST /api/v1/auth/signup`  
목적: 회원가입 시 완성된 이메일과 성별 `MALE`/`FEMALE`만 허용한다.  
흐름: 요청 DTO 검증 → 아이디·이메일 중복 확인 → 비밀번호 확인 → 기본 등급 조회 → 회원 저장.  
DB: `MEMBER`, `MEMBER_GRADE`  
주의: 성별 누락·`NONE`·형식 오류 이메일은 저장 전 `400 + VALIDATION_ERROR`로 차단한다.

API: `API-ME-002 PATCH /api/v1/me`  
목적: 로그인 회원이 이름·이메일·전화번호만 수정하고 성별은 변경하지 못하게 한다.  
흐름: JWT 회원 조회 → 성별 입력 거부 → 수정 가능 필드 검증·이메일 중복 확인 → 기존 성별 보존 저장.  
DB: `MEMBER`  
주의: `gender`가 포함된 요청은 다른 필드 변경도 함께 적용하지 않고 400으로 끝낸다.

API: `API-ME-003 PATCH /api/v1/me/password`  
목적: 현재 비밀번호와 다른 새 비밀번호로만 변경한다.  
흐름: 새 비밀번호 확인 일치 → 회원 조회 → 현재 비밀번호 확인 → 새 비밀번호의 기존 해시 일치 여부 확인 → 해시 갱신.  
DB: `MEMBER.password_hash`  
주의: BCrypt 해시는 DB 제약으로 비교하지 않고 `PasswordEncoder.matches`로 확인하며, 동일하면 갱신하지 않는다.
