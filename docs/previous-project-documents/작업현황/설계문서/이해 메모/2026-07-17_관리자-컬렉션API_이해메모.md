## API-ADMIN-COLLECTION-001 목록 조회

API: GET /api/v1/admin/collections
목적: type/status 필터로 관리자용 컬렉션 목록과 도서 매핑 수를 조회
흐름: 쿼리 검증 -> searchForAdmin(ACTIVE/HIDDEN/ENDED 전체) -> mappedCount batch 조회 -> 응답 조립
DB: collection 조회 + collection_book 건수 GROUP BY, 변경 없음
주의: 공개 API와 달리 ACTIVE로 강제하지 않는다

## API-ADMIN-COLLECTION-006 상세 조회

API: GET /api/v1/admin/collections/{collectionId}
목적: HIDDEN/ENDED 컬렉션과 HIDDEN/INACTIVE 도서 mapping까지 관리자에게 노출
흐름: collection 조회(status 무관) -> SERIES는 displayOrder ASC, EVENT는 createdAt ASC로 mapping 조회
DB: collection + collection_book 조회, 변경 없음
주의: 없는 컬렉션은 COMMON_NOT_FOUND 404

## API-ADMIN-COLLECTION-005 생성

API: POST /api/v1/admin/collections
목적: 신규 컬렉션 생성(기존 API-002 PUT은 수정 전용으로 분리)
흐름: name trim·SERIES/EVENT 교차 검증 -> Collection.create(createdBy=관리자) -> 201 + 감사 로그
DB: collection INSERT, admin_audit_log INSERT(COLLECTION_CREATE), 같은 transaction
주의: 신규 ErrorCode 없이 기존 VALIDATION_ERROR만 사용

## API-ADMIN-COLLECTION-002 수정

API: PUT /api/v1/admin/collections/{collectionId}
목적: 기존 컬렉션의 기본 정보 수정
흐름: write lock 조회 -> 교차 검증 -> mapping 있으면 유형 변경 거부(D-08) -> updateBasicInfo -> 감사 로그
DB: collection UPDATE, admin_audit_log INSERT(COLLECTION_UPDATE), 같은 transaction
주의: createdBy는 수정 시 바꾸지 않는다

## API-ADMIN-COLLECTION-003 도서 추가·정렬

API: PUT /api/v1/admin/collections/{collectionId}/books
목적: 전달된 도서만 추가/순서 갱신, 미포함 기존 mapping은 유지
흐름: write lock -> bookId 중복·존재 일괄 검증 -> SERIES는 양수·중복없는 order 필수, EVENT는 order null -> upsert
DB: collection_book INSERT/UPDATE, admin_audit_log INSERT(COLLECTION_BOOKS_UPDATE)
주의: 없는 bookId가 하나라도 있으면 BOOK_NOT_FOUND로 전체 rollback

## API-ADMIN-COLLECTION-004 도서 제외·상태 변경

API: PATCH /api/v1/admin/collections/{collectionId}
목적: status 변경과 removeBookIds 제거를 하나 이상 원자적으로 처리
흐름: status/removeBookIds 최소 1개 검증 -> write lock -> 상태 변경/mapping 삭제 -> 감사 로그
DB: collection UPDATE(선택)·collection_book DELETE(선택), admin_audit_log INSERT(COLLECTION_PATCH)
주의: 이미 제거된 bookId·동일 status 재요청도 idempotent하게 성공 처리
