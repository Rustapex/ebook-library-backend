# 2026-07-16 관리자 회원 API 이해 메모

## API-ADMIN-MEMBER-001

목적: 관리자 회원 목록·검색·필터 조회.
흐름: 필터 검증 → projection 조회 → 이메일·전화번호 마스킹 → 페이지 응답.
DB: `member`, `member_grade`, 현재 유효 `sanction_history`.
주의: `birthDate`·`gender`와 원문 PII는 DTO에 넣지 않는다.

## API-ADMIN-MEMBER-002

목적: 회원 기본 상세 또는 탭별 이력 조회.
흐름: tab 검증 → DEFAULT/탭 전용 조회 → 전용 DTO 직렬화.
DB: `member`, `book_rental`, `payment`, 신고, `point_history`, `sanction_history`.
주의: DEFAULT만 원문 PII 허용, 탭 DTO에는 profile 필드를 만들지 않는다.

## API-ADMIN-MEMBER-003

목적: 회원 상태·제재 처리와 계정 정지 만료 복구.
흐름: ADMIN/탈퇴 상태 방어 → 제재 유형별 전이 → 이력·감사 로그 transaction → 만료 배치 원인 검증.
DB: `member.current_sanction_id`, `sanction_history`, `admin_audit_log`.
주의: 계정 정지만 SANCTIONED; 원인 연결값이 없거나 불일치하면 배치는 no-op.

## API-ADMIN-MEMBER-004

목적: 관리자 포인트 지급·차감.
흐름: requestId 중복 확인 → 회원 잠금·잔액 검사 → 잔액/ADMIN_ADJUST/감사 로그 단일 transaction.
DB: `member.point_balance`, `point_history.request_id`, `admin_audit_log`.
주의: 같은 키·같은 payload는 기존 결과, 다른 payload는 409이며 음수 잔액은 불가.
