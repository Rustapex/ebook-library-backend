# 초경량 이해 메모 규칙

작성일: 2026-07-11
근거: `CLAUDE.md` "## 초경량 이해 메모 규칙" 절(신규 추가)

## 규칙 원문

> 마감이 가까운 구현 작업에서는 긴 이해노트를 매번 작성하지 않는다.
> 대신 API 구현 또는 수정 시 아래 5줄 이하 메모만 작업현황 문서에 남긴다.
>
> - API:
> - 목적:
> - 흐름:
> - DB:
> - 주의:
>
> 구현이 모두 끝난 뒤 이 메모들을 기준으로 도메인별 이해노트를 별도로 정리한다.

## 이 규칙이 왜 생겼는지

이 프로젝트의 기존 관행은 API 하나를 구현·수정할 때마다 검토보고/구현계획/체크리스트 문서를 각각 만드는 방식이었다(예: `docs/작업현황/2026-07-11_PR37_코드리뷰_대응계획.md` 같은 다단계 문서). 이 방식은 근거가 남는 대신 마감이 임박한 작업에는 비용이 크다. 그래서 급한 구현 작업에는 5줄짜리 메모만 남기고, 도메인별 정리는 나중에 몰아서 하도록 규칙을 분리했다.

기존의 "REST API 작업 시작 규칙"(검토보고 → 구현계획 → 승인)이나 "계획/구현 분리 원칙"을 대체하는 것은 아니다 — 저 규칙들은 여전히 유효하며, 이 메모 규칙은 그 문서들 작성이 부담될 만큼 급한 상황에서 최소한으로 남기는 기록 방식이다.

## 언제 쓰는가

- 마감이 가까운 구현 작업에서, API를 구현하거나 수정할 때.
- 별도의 구현계획/체크리스트 문서를 만들 여유가 없을 때.
- 이미 구현계획 문서가 있는 작업이라도, 세부 변경 하나하나에 긴 문서를 새로 만들기보다 이 메모로 충분한 경우.

## 형식

작업현황 문서(`docs/작업현황/*.md`)에 아래 5줄을 그대로 채워 넣는다. 항목당 한 줄을 넘기지 않는다.

```text
- API:
- 목적:
- 흐름:
- DB:
- 주의:
```

- **API**: API ID(있으면) + Method + URL. 예: `API-ADMIN-STAT-001 GET /api/v1/admin/statistics`
- **목적**: 이 구현/수정이 해결하는 문제 한 줄.
- **흐름**: Controller → Service → Repository 중 실제로 바뀐 경로만 한 줄로.
- **DB**: 건드린 테이블/컬럼, 또는 "DB 변경 없음".
- **주의**: 다음에 이걸 보는 사람이 반드시 알아야 할 함정 한 가지. 없으면 "없음".

## 작성 예시 (2026-07-11, §6.1 안정화 작업 기준)

```text
- API: API-ADMIN-DASHBOARD-001 GET /api/v1/admin/dashboard, API-ADMIN-STAT-001 GET /api/v1/admin/statistics
- 목적: 최근 결제 목록에 PAID 아닌 결제가 섞이는 문제 방지, 통계 count가 int overflow 위험 없이 long으로 나가게 정리
- 흐름: PaymentRepository.findRecentPayments에 WHERE paymentStatus='PAID' 추가 → AdminDashboardService는 변경 없음(같은 메서드 재사용). AdminStatisticService의 (int) 캐스팅 제거 → AdminStatisticResponse 필드 long 전환
- DB: 스키마 변경 없음, payment.payment_status 컬럼 값으로 필터링만 함
- 주의: PaymentRepository.findRecentPayments를 다른 곳에서도 쓰게 되면 "PAID만 나온다"는 전제가 깨지지 않는지 호출부마다 확인할 것
```

## 나중에(구현 끝난 뒤) 할 일

이 메모들이 쌓이면, 관리자 API 작업이 어느 정도 마무리되는 시점에 도메인별(예: 관리자 대시보드/통계/감사로그) 이해노트로 한 번에 정리한다. 그 전까지는 이 5줄 메모가 유일한 기록이라는 점을 감안해서, "목적"과 "주의" 항목만큼은 절대 비우지 않는다.
