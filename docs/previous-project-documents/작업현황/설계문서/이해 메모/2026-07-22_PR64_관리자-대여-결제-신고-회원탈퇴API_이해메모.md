# PR #64 관리자 대여·결제·신고·회원 탈퇴 API 이해 메모

API: `API-ME-004 DELETE /api/v1/me`  
목적: 탈퇴와 새 대여가 동시에 처리돼 `WITHDRAWN` 회원에게 진행 중 대여가 남는 것을 막는다.  
흐름: 회원 잠금 → ADMIN 거부 → JOINED·비밀번호·진행 중 대여 검증 → WITHDRAWN 변경.  
DB: `MEMBER` 잠금, `BOOK_RENTAL` 진행 상태 조회.  
주의: 대여 승리면 탈퇴 409, 탈퇴 승리면 뒤따른 무료/유료 대여 403이며 승리한 transaction만 유지한다.

API: 기존 무료·유료 대여 생성 경로  
목적: 탈퇴와 경합할 때 회원 상태를 최신값으로 판정한다.  
흐름: 회원 잠금 → JOINED 검증 → 진행 중 대여 검증 → 도서·콘텐츠·쿠폰·결제 저장.  
DB: `MEMBER`, `BOOK_RENTAL`, 유료 대여는 `PAYMENT`, `COUPON_USAGE`, `POINT_HISTORY`.  
주의: 탈퇴 후 요청은 모든 부수 데이터를 만들기 전에 403으로 끝난다.

API: `API-ADMIN-REPORT-001 GET /api/v1/admin/reports`  
목적: BOOK/REVIEW 통합 목록을 페이지 이동 중 중복·누락 없이 조회한다.  
흐름: 필터 적용 → `created_at DESC` → `report_id DESC` → `target_type ASC` 정렬 → page 반환.  
DB: `BOOK_REPORT`, `REVIEW_REPORT`의 독립 PK를 `target_type`까지 포함해 유일하게 정렬한다.  
주의: 같은 시각·같은 숫자 ID면 BOOK이 REVIEW보다 먼저 오며 API 필드는 바뀌지 않는다.

API: `API-ADMIN-REPORT-002 PATCH /api/v1/admin/reports/{targetType}/{reportId}/status`  
목적: 중복 신고 처리와 보호 회원 제재를 막고, 중첩 계정 정지는 안전하게 누적한다.  
흐름: 신고 잠금 → 상태 전이 검증 → 필요 시 제재 대상 회원 잠금·보호 검증 → 변경·알림·감사 로그 저장.  
DB: `BOOK_REPORT`/`REVIEW_REPORT`, `MEMBER`, `SANCTION_HISTORY`, `NOTIFICATION`, `ADMIN_AUDIT_LOG`.  
주의: 완료 신고 재처리는 409, 보호 회원 제재는 403, MySQL `1205/HY000`·`1213/40001`만 409 `CONCURRENT_UPDATE`다.
