# 2026-07-18 관리자 도서 API 이해 메모

## API-ADMIN-BOOK-001

목적: 관리자 도서 목록/검색/필터 조회(`HIDDEN`/`INACTIVE` 포함).
흐름: query 정규화 → `AdminBookSpecifications`(EXISTS 서브쿼리) 조합 → `findAll(spec, pageable)` → bookId로 저자/카테고리 bulk 조회 → 응답 조립.
DB: `book`, `publisher`, `book_author`+`author`, `book_category`+`category`.
주의: JOIN fetch로 페이지를 만들지 않는다(행 중복 방지). 상태 미지정 시 전체 상태 조회.

## API-ADMIN-BOOK-002

목적: 관리자 도서 등록(허용 메타정보만, 항상 `INACTIVE`).
흐름: 입력 검증 → publisher/author find-or-create → book·detail 저장 → category 매핑 저장 → author 매핑 저장 → 감사 로그.
DB: `book`, `book_detail`, `book_author`, `book_category`, `publisher`, `author`, `admin_audit_log`.
주의: `keywords[]`/`file`/`pages[]`/`status`는 요청에 없음. ISBN 중복은 409.

## API-ADMIN-BOOK-003

목적: 관리자 도서 수정(허용 메타정보 전체 교체, 원문·키워드 보호).
흐름: write lock(5초, 세션변수 복원) → 입력 검증 → scalar/detail 갱신 → 기존 author/category 매핑 삭제 → 새 매핑 저장 → 감사 로그.
DB: `book`, `book_detail`, `book_author`, `book_category`, `admin_audit_log`.
주의: `BookPage`/키워드/`rentalCount`/`averageRating`/`reviewCount`/`totalPages`는 변경 안 함. 동시 수정은 409.

## API-ADMIN-BOOK-004

목적: 도서 상태 변경(물리 삭제 없음).
흐름: write lock(5초, 세션변수 복원) → status 검증 → 상태 변경 → 감사 로그(`reason` 포함).
DB: `book.status`, `admin_audit_log`.
주의: `AVAILABLE`/`HIDDEN`/`INACTIVE`만 허용. `reason`은 감사 로그에만 남고 별도 컬럼 없음.
