[ABC 발표·시연 연습용 DB 데이터 준비 요청 – 최종본]

안녕하세요. ABC 프로젝트 발표와 반복 시연 연습을 위해 아래와 같이 시연용 DB 데이터 준비를 요청드립니다.

시연 예정일: [YYYY-MM-DD]
대상 DB: [시연 DB명]
시연 지역: [예: 서울특별시 강남구]

중요 요청사항:
- 신규 도서 생성은 가급적 하지 않고 현재 DB에 존재하는 도서를 활용해주세요.
- 사용자 시연 연습을 반복할 수 있도록 동일 조건의 USER 계정 5개가 필요합니다.
- 5개 계정은 login_id, 이메일, 연락처만 서로 다르고 나머지 시연 데이터 조건은 동일해야 합니다.
- 시연 데이터는 운영·공용 데이터와 구분되는 접두어를 사용해주세요.
- 반복 적용 시 중복되지 않는 형태로 작성해주세요.
- 적용 전 백업 또는 복구 가능한 스냅샷을 남겨주세요.
- 백엔드 초기화 SQL 실행 후에도 시연 데이터가 유지되는지 확인해주세요.
- 비밀번호 평문은 SQL이나 공용 문서에 기록하지 말고 별도로 전달해주세요.

────────────────────────────────────
1. 시연 계정 구성
────────────────────────────────────

1) 관리자 계정 1개

- role: ADMIN
- 정상 로그인 가능
- 관리자 대시보드, 도서, 외부 도서, 공지, 통계 화면 접근 가능
- 발표 전용 계정
- login_id 및 member_id 회신 요청

2) 동일 조건의 USER 계정 5개

권장 login_id:
- abc_demo_user01
- abc_demo_user02
- abc_demo_user03
- abc_demo_user04
- abc_demo_user05

공통 조건:
- role: USER
- status: JOINED
- 동일한 회원 등급
- 동일한 포인트·쿠폰·출석·챌린지·대여·결제·알림·서재 조건
- login_id, 이메일, 연락처는 서로 다름
- 프로필 수정과 비밀번호 변경이 가능한 전용 계정
- 각 계정은 서로 영향을 주지 않고 같은 사용자 시연을 한 번씩 진행할 수 있어야 함
- 5개 계정 모두 제재 상태가 아니어야 함

계정별로 다음 초기화·복구 SQL도 부탁드립니다.
- 프로필 원복
- 비밀번호 원복
- 포인트 원복
- 쿠폰 사용 상태 원복
- 신규 결제·대여 원복
- 신규 리뷰·평점 원복
- 신규 즐겨찾기 원복
- 신규 도서·리뷰 신고 원복
- 출석과 챌린지 진행도 원복
- 북마크와 독서 진행률 원복

3) 회원가입 중복 확인용 계정 1개

- 기존에 존재하는 login_id
- 정상 가입 상태
- USER 시연 계정 5개와는 별도 계정
- 발표 중 아이디 중복 확인 실패 시연에 사용

신규 회원가입에 사용할 login_id와 이메일은 DB에 존재하지 않도록 확인 부탁드립니다.

4) 제재 회원 표시용 별도 계정

- USER 시연 계정 5개와 별도로 최소 2개
- status: SANCTIONED
- 유효한 sanction_history 존재
- ACCOUNT_SUSPENSION, REVIEW_BAN 또는 RENTAL_BAN 이력 구성
- 관리자 대시보드의 제재 회원 수가 0이 아니도록 설정

────────────────────────────────────
2. USER 계정 5개 공통 데이터
────────────────────────────────────

각 USER 계정에 아래 조건을 동일하게 적용해주세요.

A. 포인트와 쿠폰

- point_balance 최소 1,000포인트 이상
- 권장 잔액: 3,000포인트
- point_history 합계와 현재 잔액 일치
- 결제에 사용할 수 있는 유효 쿠폰 1개
- 권장 쿠폰: 10% 할인
- 쿠폰 상태 ACTIVE
- 회원 쿠폰 상태 ISSUED
- 시연일 이후까지 유효
- 아직 사용하지 않은 상태

B. 출석

- 시연일 직전 6일 동안 연속 출석
- 시연 당일 출석 데이터는 없음
- 시연 중 당일 출석하여 7일 연속 출석이 되도록 구성

C. 출석 챌린지

현재 출석 7일 달성 자체에서는 쿠폰이 자동 발급되지 않으므로 다음 흐름으로 준비해주세요.

출석 → 챌린지 달성 → 보상 수령 → 쿠폰 확인

필요 데이터:
- ACTIVE 상태의 DAILY 출석 챌린지
- ACTIVE 상태의 TOTAL 출석 챌린지
- target_action: ATTENDANCE
- target_count: 1
- 시연 당일 progress 없음
- reward_claimed_at 없음
- 보상 수령 전에는 보상 쿠폰이 발급되지 않은 상태
- 한 챌린지는 포인트 보상, 한 챌린지는 쿠폰 보상 권장

대여·리뷰 챌린지는 현재 실제 행동과 자동 연결되지 않으므로 화면과 보상 수령만 보여줘야 한다면 다음과 같이 준비해주세요.

- RENTAL 챌린지: 달성 완료, 보상 미수령
- REVIEW 챌린지: 달성 완료, 보상 미수령
- 발표 화면 표시용 사전 달성 데이터로 구분

D. 기존 마이페이지 데이터

각 계정에 동일하게 준비해주세요.

내 서재:
- 기존 대여 도서 여러 권
- 이어보기 가능한 도서 최소 1권
- 이어보기 도서에 유효한 reading_progress 존재
- 스크롤할 정도의 대여 목록

알림:
- 과거 알림 여러 건
- 읽음·안 읽음 상태 혼합
- 발표 중 발생하는 신규 대여·결제 알림이 최신으로 추가될 수 있어야 함

결제내역:
- 기존 성공 결제 최소 2건
- 결제일이 서로 다름
- 쿠폰 사용 결제 1건
- 포인트 사용 결제 1건
- payment와 book_rental 관계 정상

신고내역:
- 기존 신고내역 1건 정도
- 발표 중 신고할 대상 도서와 리뷰에 대한 기존 신고는 없음

프로필:
- 이름, 이메일, 연락처 존재
- 변경할 이메일과 연락처가 다른 회원과 충돌하지 않음
- 비밀번호 변경 가능한 정상 비밀번호 해시

────────────────────────────────────
4. 사용자 시연 핵심 도서
────────────────────────────────────

A. “Why? 정보통신 - 2판”

기존 도서를 활용해주세요.

필수 조건:
- AVAILABLE 상태
- 표지, 저자, 출판사, ISBN, 소개 존재
- 카테고리 연결
- 추천 도서 노출 가능
- 다른 회원의 활성 리뷰와 평점 최소 3개
- review_count와 average_rating 집계값 일치
- USER 시연 계정 5개 모두 이 도서에 대한 기존 신고 없음

B. “나도코딩의 파이썬 입문”

표시 제목은 “나도코딩의 파이썬 입문”으로 통일해주세요.
기존 도서가 다른 이름이라면 최종 사용 도서명과 book_id를 회신해주세요.

필수 조건:
- 기존 도서 활용
- AVAILABLE 상태
- 유료 도서
- 권장 가격 5,000원 이상
- 표지, 저자, 출판사, 소개, 카테고리 존재
- 숫자 13자리 ISBN 존재
- 추천 도서 노출 가능
- 다른 회원 리뷰·평점 최소 3개
- review_count와 average_rating 일치

USER 시연 계정 5개 각각에 대해:
- 기존 즐겨찾기 없음
- 기존 리뷰와 평점 없음
- 기존 활성 대여 없음
- 기존 결제 없음
- 기존 북마크 없음
- 기존 독서 진행률 없음

발표 중 다음 순서로 진행합니다.

결제·대여 → 뷰어 첫 진입 → 북마크와 진행률 저장 → 리뷰 작성

────────────────────────────────────
5. EPUB 시연용 기존 도서 2권
────────────────────────────────────

신규 도서를 생성하지 않고 기존 도서 2권만 지정해주세요.

1) EPUB 보유 도서 1권

권장:
- “나도코딩의 파이썬 입문”을 EPUB 보유 도서로 사용

조건:
- 유효한 book_epub 데이터 존재
- 실제 EPUB 열람 가능
- 목차 존재
- 여러 구간으로 구성
- 처음 이동 가능
- 목차 이동 가능
- 북마크 4개를 서로 다른 위치에 생성 가능
- 마지막 읽은 위치 저장 가능
- 재진입 시 마지막 위치 복원 가능

이 도서는 사용자 뷰어 시연용이므로 관리자 EPUB 업로드 연습 대상으로 사용하지 않습니다.

2) EPUB 미등록 도서 1권

조건:
- 기존 DB에 존재하는 도서
- 신규 도서 생성 금지
- 발표 전 book_epub 데이터가 없어야 함
- 관리자 화면에서 검색 가능한 도서
- 다른 사용자의 대여·독서 진행률·북마크가 없는 도서
- 사용자에게 노출할 필요가 없다면 HIDDEN 상태 권장
- 관리자 EPUB 직접 등록 시연 대상으로 사용

EPUB 파일 내용과 도서명이 일치하지 않아도 괜찮습니다.
EPUB 업로드 기능 확인용 파일로만 사용합니다.

업로드용 EPUB 파일:
- 유효한 .epub 파일
- 50MB 이하
- DRM 또는 암호화되지 않은 파일
- EPUB 내부 mimetype과 META-INF/container.xml 정상
- 파일명을 별도로 회신
- 발표 PC에서 바로 선택할 수 있도록 전달

관리자 시연 흐름:
- 외부 도서 등록 화면 접속
- 외부 도서 후보 목록 확인
- 기존 EPUB 미등록 도서의 book_id 입력
- EPUB 파일 선택
- 업로드 확인창 확인
- EPUB version 1 등록 성공 확인
- 필요하면 관리자 도서 수정 화면에서도 EPUB 등록 상태 확인

신규 외부 도서 승인으로 실제 도서를 생성하는 작업은 하지 않습니다.
기존 도서에 EPUB 본문을 등록하는 기능까지만 시연합니다.

────────────────────────────────────
6. 외부 도서 등록 화면용 후보 데이터
────────────────────────────────────

외부 API 장애나 인증 설정과 관계없이 화면 목록을 확인할 수 있도록 book_isbn_temp 데이터를 준비해주세요.

최소 조건:
- READY 상태 후보 최소 2건
- PENDING 상태 후보 최소 1건
- MERGED 상태 후보 최소 1건
- ISBN13 숫자 13자리
- 제목, 저자, 출판사, 표지 URL, 설명 존재
- 외부 분류명 존재
- 갱신일이 최근 날짜

중요:
- READY 후보의 승인 버튼은 확인만 하고 실제 승인하지 않을 예정
- 실제 승인 시 신규 book이 생성되므로 발표에서는 실행하지 않음
- EPUB 직접 등록은 앞에서 지정한 기존 EPUB 미등록 도서에 수행

7. 리뷰와 신고
────────────────────────────────────

“나도코딩의 파이썬 입문”에 다른 회원이 작성한 신고용 리뷰 1개를 준비해주세요.

리뷰 내용:
- 나도코딩 재미 없어요!

조건:
- USER 시연 계정 5개가 아닌 별도 회원 작성
- ACTIVE 상태
- USER 시연 계정 5개 모두 이 리뷰를 신고한 기록 없음

각 USER 계정은 다음 작업이 가능해야 합니다.
- 결제 후 뷰어 진입
- 자신의 리뷰와 평점 신규 작성
- 다른 회원의 “나도코딩 재미 없어요!” 리뷰 신고
- 마이페이지 신고내역에서 신규 신고 확인

관리자 대시보드와 신고 관리용 데이터:
- 도서 신고 최소 3건
- 리뷰 신고 최소 3건
- WAITING, PROCESSING, DONE 상태 혼합
- 최근 신고 목록에 표시될 최근 데이터 최소 5건
- 신고 총합이 0이 아니어야 함

────────────────────────────────────
8. 컬렉션
────────────────────────────────────

기존 도서를 이용해 컬렉션 2개를 준비해주세요.

1) 시리즈 컬렉션

- collection_type: SERIES
- 상태 ACTIVE
- 기존 AVAILABLE 도서 최소 5권
- display_order 중복 없음
- 예시 제목: Why? 시리즈 모아보기

2) 할인 컬렉션

- collection_type: EVENT
- 상태 ACTIVE
- 시연일이 start_at과 end_at 사이
- 할인율 10~20%
- 기존 AVAILABLE 도서 최소 5권
- “나도코딩의 파이썬 입문” 포함 권장
- 예시 제목: 파이썬 입문 할인전

두 컬렉션 모두 메인페이지에 노출되고 더보기 화면에서 도서 목록이 조회되어야 합니다.

────────────────────────────────────
9. 공지사항과 관리자 공지 관리
────────────────────────────────────

공지사항을 최소 5개 이상 준비해주세요.

권장 구성:
- ACTIVE 공지 6개 이상
- HIDDEN 공지 1개 이상
- 최근 작성 공지 1개
- 일반 안내 공지
- 서비스 점검 공지
- 신규 도서 안내
- 이벤트 안내
- 쿠폰 안내
- 이용 정책 안내

필수 조건:
- 제목과 본문이 자연스럽게 작성됨
- 작성일이 모두 동일하지 않도록 분산
- 관리자 공지 목록에서 5개 이상 확인 가능
- ACTIVE/HIDDEN 필터 확인 가능
- 사용자 공지 목록에는 ACTIVE 공지만 노출
- 사용자 공지 상세의 이전글·다음글 확인 가능
- 메인페이지 공지 영역에는 가장 최근 ACTIVE 공지가 노출

────────────────────────────────────
10. 관리자 대시보드
────────────────────────────────────

관리자 대시보드 주요 수치가 0으로만 표시되지 않도록 준비해주세요.

반드시 0보다 커야 하는 항목:
- 전체 회원 수
- 제재 회원 수
- 이용 가능 도서 수
- 전체 대여 수
- 무료 대여 수
- 유료 대여 수
- 완독 수
- 결제 합계
- 활성 리뷰 수
- 도서 신고 + 리뷰 신고 합계

권장 최소값:
- 제재 회원: 2명 이상
- 활성 도서: 10권 이상
- 대여: 10건 이상
- 완독: 10건 이상
- 결제 성공: 5건 이상
- 활성 리뷰: 10건 이상
- 신고: 6건 이상

최근 내역도 비어 있지 않게 준비해주세요.
- 최근 결제 5건
- 최근 신고 5건
- 최근 희망도서 후보 5건

USER 시연 계정 5개는 정상 회원으로 유지하고, 제재 회원과 신고 피신고자는 별도 계정을 사용해주세요.

────────────────────────────────────
11. 관리자 통계 – 완독 추이
────────────────────────────────────

통계 관리 화면에서 완독 추이가 0으로 평평하게 보이지 않도록 reading_progress 데이터를 준비해주세요.

현재 TOTAL 통계의 추이는 최근 12개월을 월별로 집계합니다.

필수 조건:
- 최근 12개월 안에 completed_at이 있는 완독 데이터 존재
- 최소 6개 이상의 서로 다른 월에 분산
- 월별 완독 수가 서로 달라 그래프 높이 차이가 보이도록 구성
- 각 reading_progress는 실제 member 및 book_rental과 연결
- completed_yn = true
- completed_at 존재
- progression은 완독 상태에 맞는 값
- 동일 대여의 중복 완독 데이터 생성 금지

권장 예시:
- 6개월 전: 1건
- 5개월 전: 2건
- 4개월 전: 4건
- 3개월 전: 3건
- 2개월 전: 5건
- 1개월 전: 2건
- 현재 월: 4건

연습용 USER 계정의 내 서재 데이터와 충돌하지 않도록 기존 별도 회원 또는 통계 전용 회원의 대여·진행률을 활용해도 됩니다.

“완독 추이만 그래프가 보이도록”이라는 요청은 화면에서 다른 그래프를 숨기는 의미가 아니라, 완독 추이 그래프에 실제 월별 값이 보이도록 데이터를 준비해달라는 의미입니다.

- 도서 가격: 5,000원
- 쿠폰 할인: 500원
- 포인트 사용: 1,000포인트
