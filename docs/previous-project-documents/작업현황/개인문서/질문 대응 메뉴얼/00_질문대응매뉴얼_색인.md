# ABC 질문 대응 매뉴얼 색인

## 1. 문서 목적

이 매뉴얼은 ABC(Acorn Book Cloud) 프로젝트 발표·면접·질의응답에서 다음 내용을 실제 근거에 맞춰 설명하기 위한 문서다.

- 무엇을 왜 만들었는가
- 실제로 어떻게 구현했는가
- 설계와 구현은 무엇이 다른가
- 구현하지 못했거나 제외한 기능은 무엇인가
- 테스트와 배포는 어디까지 확인했는가
- 본인이 맡고 판단한 범위는 무엇인가

질문은 반드시 다음 계층으로 배치한다.

```text
키워드
└─ 도메인
   └─ 질문 유형
      └─ 질문 → 답변
```

`압박 질문`, `꼬리질문`, `기본 질문`은 별도 키워드로 중복 작성하지 않고 각 질문의 난이도와 후속 질문으로 표시한다.

원격 fetch는 실행하지 않았다. 사용자가 최신이라고 지정한 두 로컬 작업 트리와 현재 파일 내용을 기준으로 조사했다.

### 2.2 근거 우선순위

1. 현재 Backend·Frontend 소스와 테스트
2. Backend 런타임 스키마 `src/main/resources/schema.sql`
3. 최종 API 명세와 백엔드 공통 개발 규칙
4. PR·코드리뷰·작업현황의 검증 기록
5. Front 화면·배포 문서
6. 발표 대본과 개인 포트폴리오 문서
7. 팀 진행 사실
8. 외부 면접 자료와 예상 질문 모음

문서와 소스가 다르면 실제 구현 설명은 현재 소스를 우선한다. 설계 의도는 설계문서로 설명하되 차이를 숨기지 않는다.

### 2.3 이번 조사에서 확인한 문서 시점 차이

- `docs/프로젝트현황/API-ID별_백엔드구현_프론트연결_현황.md`는 83개 판정 대상 중 Backend 76개, Front 연결 69개라는 정적 스냅샷을 제공한다.
- 이후 로컬 Front 소스에는 도서관 `region`·페이지 응답 정합화와 관리자 대여·결제·신고 실제 호출이 추가돼 있다.
- Front 화면 설계서의 일부 “controller 미확인” 표는 과거 시점 기록이다. 현재 Backend에는 회원·도서·대여·결제·신고·희망도서·공지·컬렉션 Controller가 추가돼 있다.
- 따라서 과거 현황표의 합계는 개발 과정 설명에는 사용할 수 있지만 현재 최종 구현 개수로 단정하지 않는다.

## 3. 상태 표기

| 상태 | 의미 |
|---|---|
| `구현 확인` | 현재 소스에서 처리 경로를 확인함 |
| `구현·연동 확인` | Backend endpoint와 Front 호출부를 정적으로 확인함 |
| `자동 테스트 근거 있음` | 관련 테스트 파일 또는 과거 성공 기록이 있음 |
| `배포 코드 확인` | workflow·배포 설정은 확인했으나 이번 조사에서 실제 배포를 실행하지 않음 |
| `부분 구현` | 핵심 흐름 일부만 구현됨 |
| `설계와 다르게 구현` | 명세·화면설계와 현재 소스가 다름 |
| `최종 범위 제외` | 팀이 구현하지 않기로 정한 기능 |
| `구현되지 않음` | 설계 또는 화면은 있지만 현재 처리 경로가 없음 |
| `설정상 비활성 가능` | 코드가 있어도 환경 설정에 따라 사용할 수 없음 |
| `실행 확인 필요` | 정적 소스는 확인했지만 현재 배포 환경의 실제 성공은 확인하지 않음 |
| `팀 확인 필요` | 코드로 확인할 수 없는 개인 경험·역할·의사결정 |

## 4. 질문 답변 작성 형식

```markdown
#### [난이도][상태] Q. 질문

**짧은 답변:** 20~30초 답변

**상세 답변:** 구현 의도, 실제 처리, 설계 차이, 한계를 포함한 답변

**근거:** 소스·테스트·문서 경로

**예상 꼬리질문:** 이어질 수 있는 질문
```

확인되지 않은 내용을 채우기 위해 추측하지 않는다. 구현 여부와 실행 여부를 구분하고, “코드가 있다”와 “현재 배포에서 정상 동작한다”도 구분한다.

## 7. 사용 방법

1. 질문의 관점을 보고 키워드를 선택한다.
2. 질문 대상 기능이나 기술 도메인을 선택한다.
3. 목적·정책·흐름·예외·검증·차이 중 질문 유형을 찾는다.
4. 짧은 답변을 먼저 말한다.
5. 추가 질문이 오면 상세 답변과 근거를 사용한다.
6. 현재 소스나 배포 상태가 바뀌면 색인의 기준 커밋과 해당 답변 상태를 함께 갱신한다.
